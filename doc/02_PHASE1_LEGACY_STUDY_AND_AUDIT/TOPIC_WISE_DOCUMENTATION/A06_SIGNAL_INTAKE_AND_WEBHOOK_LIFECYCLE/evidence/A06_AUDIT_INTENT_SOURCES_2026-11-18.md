### 1.3 Kinds, dates and labels

- Kinds: INTENT (a decision, requirement, build instruction, design rule, fix direction or procedure), DECLARATION (a docstring, code comment, configuration comment, name, log or response text, code default), DECISION (a recorded decision of the legacy team or of Rama, with its date), RECORD (a legacy audit, investigation, status or running-log document describing the system or a finding), CONFIG (a committed configuration value), TEST (a test or an A19 script: stated expectations only, never run), EXTERNAL (Chartink's own public help pages, read on the date given; current external context, not a fact about the legacy period).
- Dates: a bare date is the file's last change at `970aabf`; "lines D" is the author-date range of the cited lines by `git blame` at the baseline (hashes and dates only); "commit D" is the date of a cited commit. Every legacy source is HISTORICAL: it shows what someone intended or believed at its date, never what the code does or did. Runtime claims inside sources (request counts, "deployed", "measured", "no listener", "does not exist on the VM") are UNKNOWN / NOT ESTABLISHED as runtime facts.
- Owner topics of non-A06 files are named in brackets per the Master System Investigation Index; such passages are cited only for their stated intent at the A06 boundary. A Phase 2 input or treatment recorded in a project register is not a legacy intent source; where one might be mistaken for one, that is said (section 5).
