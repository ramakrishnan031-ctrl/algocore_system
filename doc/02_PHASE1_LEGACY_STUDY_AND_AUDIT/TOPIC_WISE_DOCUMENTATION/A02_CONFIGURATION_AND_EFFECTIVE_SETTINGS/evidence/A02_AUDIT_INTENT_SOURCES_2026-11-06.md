### 1.2 Kinds, dates and labels

- Kinds (as A01): INTENT (a decision, requirement, instruction, design rule or fix direction), DESCRIPTION (how the system works or worked, or a recorded finding), DECLARATION (a configuration value, comment, docstring, name, log or alert text, code default), TEST (a test expectation or test plan; documentary only).
- Dates: a bare date is the file's last change at 970aabf (`git log -1`); "lines D" is the author date range of the cited lines (`git blame`); "commit D" is the date of a cited commit. Every source is HISTORICAL documentary evidence of what someone intended or believed at its date; none proves that anything was installed, ran or was in force (Document 08, section 10; UNKNOWN / NOT ESTABLISHED for runtime).
- A configuration value is "the file value at the baseline". A code default is cited as a DECLARATION, not as an intent of Rama.
- Owner topics of non-A02 files are named in brackets per the Master System Investigation Index, section 3 and Appendix A.
- Security: no credential value, account identifier, personal name, e-mail address, IP address, home path or session link is reproduced. Per-account variable names are written `ZERODHA_API_KEY_<ACCOUNT_ID>`. Passages that hold such material are cited by line only (section 7, last bullet).
