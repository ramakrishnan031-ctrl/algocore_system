### 1.3 Method and labels

- Scope: every statement in the five records about configuration (files and purpose, keys and values, defaults, schemas and validation, the loader, validator, auditor and snapshotter, strategy configuration, environment variables and `.env`, configuration hashes, snapshots and change detection, the TEMP-config mechanism, and the configured side of times, limits and flags). Claims about `config/cron_registry.yaml` contents are listed as OUTSIDE A02 (A16) and not checked. Start-up claims already checked by A01 are not repeated; where a configuration claim was also in the A01 check, the A01 ID is cited.
- Result labels: MATCH; PARTLY (which part); DIFFERS (how); OUTSIDE A02 (owner topic from the Master System Investigation Index, section 3 "Paths" and Appendix A; not checked); NOT CHECKABLE FROM CODE (machines, captures, record method); paper-only (branch point marked, not traced). A line-number difference alone is not a difference. A module or key that the records describe and that does not exist at 970aabf is DIFFERS when it is the whole claim and PARTLY when it is part of the claim. Each result is FACT from the cited baseline lines unless it says INTERPRETATION. Counts use the first label of the Result cell.
- Record 02 is checked in four parts:
  - (a) its entries for the A02-owned modules and its structural statements, claim by claim;
  - (b) every consumer entry that names, as a file it reads, a `config/…` path or a configuration file by its bare name (found by a pattern search of the record); only the presence of the file name in the consumer at 970aabf is checked, and the record's line anchors there were not individually re-checked. Two kinds of entry fall outside that search and have no row in 2.2b: the entry at Record 02 L2537 (`utils/startup_checks.py`), which names its files under `config_dir` (its presence, hash, strategy and TEMP checks are covered by R3-13, R3-15 and R3-30); and three entries (Record 02 L2998, L3056 and L3336) that name `accounts.csv` only as the source of the API-key variable name read through the account registry;
  - (c) every "Config keys read" field of a non-A02 module, mechanically (each cited key: is its last name segment on the cited line at 970aabf, within 3 lines, or elsewhere in a file whose length changed; and is the token a key of a baseline configuration file);
  - (d) its statements that scripts load `.env`.
- Tools: scripts kept outside the clone, run with `python3 -I`, which read file text with `git show` and parse it with `ast` and `yaml.safe_load`. The library behaviour cited for python-dotenv was read from the source of version 1.2.3 installed in the study environment (the repository pins 1.2.2, `requirements.txt` L14).
- Security: no credential value, account identifier, address, e-mail address or home path is reproduced. Environment-variable names that carry an account suffix are written `<account>`. For `config/accounts.csv` only column names and row count are given (and the primary-row count, as in A01 R1-07).
