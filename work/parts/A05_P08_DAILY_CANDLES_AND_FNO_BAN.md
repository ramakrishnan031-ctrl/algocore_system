P08-S038. INTERPRETATION (the A05 side of A03 Q-16; SQLite semantics, own check P08-S003): `OR IGNORE` skips a row silently, with no exception, in two cases that arise on this path. (a) A row whose `(instrument_token, ts, 60)` is already stored: in a re-run for the same date, the minutes already stored keep their first-written values, even if the server's values for them have changed since (a later correction, or a candle that was still forming at the earlier run, P08-S031). Because `inserted` counts executes, not inserted rows, the printed count includes skipped rows (L321, L326). The handler for `sqlite3.IntegrityError` (L322) is not reached by these cases: `OR IGNORE` covers UNIQUE, NOT NULL and CHECK constraints, and the table declares no FOREIGN KEY (`core/analytics_schema.sql` L14 to L17), so at the baseline schema no constraint of this table makes the statement raise that error.

P08-S039. INTERPRETATION (Python `sqlite3` legacy transaction semantics: an implicit `BEGIN` before the first INSERT; basis P08-S036): all rows of one call form one transaction, committed once at L324.
