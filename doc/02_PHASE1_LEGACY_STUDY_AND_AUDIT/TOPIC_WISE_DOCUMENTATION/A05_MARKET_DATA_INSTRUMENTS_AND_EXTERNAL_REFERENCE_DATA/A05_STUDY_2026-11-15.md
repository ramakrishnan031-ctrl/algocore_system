## 2. Market data in brief

A summary for orientation, for a reader new to A05; each point is established in the section named, with its evidence. Nothing here says what ran in production: every runtime fact is UNKNOWN / NOT ESTABLISHED (section 1.6).

```
 trading process (one per start)
   config/instruments.csv --load once--> InstrumentCache --> token map, lookups
   broker WebSocket --> LiveFeedManager --queue--> consumer --> _tick_dispatcher
                                                     |          |--> CandleStore --close--> smart TGT, structure exit,
                                                     |          |                           _persist_candle --> candles
                                                     |          '--> shadow tracker (A11)
                                                     '--> exit-retry callback (A10)
   broker REST --> main.py closure ("historical" bucket) --> six OhlcFetcher consumers --> candle_math (A08, A18)
 scripts (each its own process and client)
   refresh_instruments --> config/instruments.csv     fetch_daily_candles --> candles + candle CSV
   fetch_fno_ban --> fno_ban table                    find_symbol_aliases --> candidate lines on stdout
```

- **The instrument cache.** At boot the trading process loads the instrument master `config/instruments.csv` once into one `InstrumentCache`, which every consumer receives; nothing reloads it, so a refreshed file reaches the process only at its next start. A missing file or fewer than 1,000 rows stops the start with exit 3; a present but unloadable file ends in exit 2 when no other start check blocks first (A01 C9) (section 8) (P05-S051, P05-S053, P05-S063, P12-S026).
- **The live feed.** One `LiveFeedManager` opens one `KiteTicker` WebSocket and asks only for LTP mode. Each tick becomes a six-key dictionary, goes through a bounded queue to one consumer thread, and is dispatched to `_tick_dispatcher` (the candle store, then the shadow tracker, A11) and, once an exit retry has registered it, to the order placer's callback (A10). No token is subscribed at boot. A later subscription depends on the exit-retry path. Whether that path ever ran in production is UNKNOWN / NOT ESTABLISHED (section 3) (P01-S026, P01-S036 to P01-S038, P01-S041, P01-S042, P01-S044, P01-S047, P01-S057).
- **The candle store.** It builds one-minute candles by the host clock: real candles from the LTPs it is given, and synthetic flat candles for silent tokens that already have history. It keeps the last 500 per token in memory and hands each closed candle to the smart-target manager, the structure-exit manager (only when its switch is on; committed value off) and `_persist_candle`, which inserts it into the `candles` table. A live candle's `ts` is the time its close ran, and its volume is 0 for LTP ticks. No token is subscribed at boot. A later subscription depends on the exit-retry path. Whether that path ever ran in production is UNKNOWN / NOT ESTABLISHED (section 5) (P03-S041, P03-S045, P03-S047, P03-S066, P03-S071, P03-S078, P03-S119, P03-S127).
- **Historical candles in the trading process.** One closure over the live REST client and the limiter's `historical` bucket is built once at boot when any of six feature flags is on. Six consumers use it, each through its own `OhlcFetcher` with an in-memory cache: the V1 detector, the structure fetcher and the one-minute retest fetcher (A08), and the regime, V3 chain and PB-01 watchlist fetchers (A18). At the committed values three of the flags are on. Nothing on this path is stored (section 7) (P06-S015, P06-S016, P06-S022, P06-S030, P06-S032, P12-S017, P12-S018).

## 3. The live feed and tick intake (questions A1 to A8)

This section covers `data/live_feed.py` and its market-data call sites in `main.py`: construction and start, subscriptions, tick intake and normalisation, the queue and the consumer, the close, error, reconnect and stale-feed paths, and what the feed publishes. Evidence: the live-feed evidence (P01), which covers `data/live_feed.py` L1 to L790 in whole, its construction, start, dispatch and shutdown lines in `main.py`, and its one subscribing caller in `orders/order_placer.py` (A10's file, boundary only).

**Entry point and construction (A1).**

- FACT: the trading process builds one `LiveFeedManager`, in `_main_locked` at `main.py` L2927, and starts it with `live_feed.connect()` at L3947. No other non-test file constructs `LiveFeedManager` or `KiteTicker` (P01-S026). The start order is `candle_store.start()`, the candle writer's registration, the candle store's token map, then `live_feed.connect()`, all before `_install_signal_handlers()` at L3958 (A01 C14) (P01-S027, P01-S122).
- FACT: `main.py` passes six arguments: the API key, read from the environment variable whose name the selected account row's `api_key_env` field holds; the access token, read from `ZERODHA_ACCESS_TOKEN`; the critical-failure callback; a logger; the paper flag; and the market windows. It does not pass `kill_switch` or any of the five tuning arguments (reconnect attempts and delay, stale threshold, check interval, slice size) (P01-S147).
- FACT: in Live, `connect()` clears the stop event, starts the consumer thread and the watchdog, builds the `KiteTicker` with the key, the token, `reconnect_max_tries` and `reconnect_max_delay`, and calls the library's `connect(threaded=True)`. It has no `try` and no guard against a second call; the paper branch returns first (paper-only, not traced) (P01-S016, P01-S017, P01-S123).
- FACT: the key and token are stored unchanged, never checked beyond logging whether each is set, and never replaced for the life of the process (P01-S011, P01-S124). A04 CL-27 records that the empty-string defaults cannot be reached in the only reachable Live start (P01-S125).

**Upstream feed, subscriptions and instrument mapping (A2).**

- FACT: the upstream feed is the library's `KiteTicker` WebSocket; the feed sets six of its nine callbacks and leaves `on_open`, `on_message` and `on_order_update` unset (P01-S017, P01-S020). The only mode the code ever requests is LTP (P01-S042).
- FACT: `subscribe()` records new tokens in `_subscribed` and, only while connected, sends them in slices of 50 with `set_mode(MODE_LTP)`; `_on_connect` re-sends every tracked token without slicing, in one `subscribe` and one `set_mode(MODE_LTP)` call, catches any failure and logs it as CRITICAL (P01-S029, P01-S033).
- FACT: `main.py` never calls `subscribe` on the feed, and `_subscribed` starts empty, so the first `_on_connect` sends nothing (P01-S035). The only non-test caller is `orders/order_placer.py` L3404, inside `_add_to_exit_retry`, which runs when a stop-loss exit placement fails with what the code treats as an LTP validation error (broker code 16418, or a message containing "trigger price" or "ltp cannot be validated"); the token comes from the instrument cache by symbol (P01-S036, P01-S037, P01-S148).
- FACT and UNKNOWN / NOT ESTABLISHED: No token is subscribed at boot. A later subscription depends on the exit-retry path. Whether that path ever ran in production is UNKNOWN / NOT ESTABLISHED (P01-S038).
- INTERPRETATION: a subscribed token stays tracked for the rest of the process (no non-test `unsubscribe` caller) and is re-sent at every later connect; the effect counter counts every `subscribe` call, and its only report is the effect-census line written when `_shutdown` runs (P01-S012, P01-S032, P01-S039).
- INTERPRETATION: the feed works on instrument tokens only and holds no symbol, exchange or tradingsymbol mapping; the subscribing caller maps symbol to token before, and the consumers map token to symbol after (P01-S058).

**Decoding, validation, time stamps and normalisation (A3).**

- FACT: packet decoding is the library's (section 4). For each non-empty batch `_on_ticks` first records `_last_tick_at = now_ist()`, read only by the watchdog; INTERPRETATION: it is the batch's receipt time in IST (P01-S040, P01-S075).
- FACT: each raw tick becomes a new dictionary with six keys: `instrument_token`; `last_price` as `float(...)`, 0.0 when absent; `bid` and `ask`, 0.0 unless depth is present; `timestamp`, the library's `exchange_timestamp` or else `timestamp`; and `volume`, the library's `volume_traded`. No other key is read. Apart from the `float()`, nothing is converted, localised, rounded or validated, and no receipt time is added to the tick (P01-S041, P01-S042).
- INTERPRETATION: for an 8-byte LTP packet, as the published parser builds it, the tick carries `timestamp` None and `volume` None. `_tick_dispatcher` then passes the candle store `now_ist()`, read on the consumer thread at dispatch, and a volume of 0 (P01-S055, P01-S149). Which packets the server sent in the legacy period is UNKNOWN / NOT ESTABLISHED (P01-S143).
- FACT: before dispatch the consumer drops, at DEBUG only, any tick whose token is None or whose price is None or 0.0 (P01-S048).

**Duplicate, out-of-order, delayed, missing and malformed ticks (A4).**

- FACT: the feed compares no time stamps and keeps no per-token last value; it does not handle duplicate, out-of-order, delayed or late ticks, and does not drop ticks for tokens it did not subscribe. Missing ticks show only as the whole connection's tick age, through the watchdog (P01-S049, P01-S081).
- INTERPRETATION: a `None` or non-numeric `last_price` would make `float()` raise inside `_on_ticks`, outside any `try`, after the earlier ticks of the batch were queued; the published parser does not produce such a value (P01-S043).

**Reconnect, resubscription, disconnect and stale feed (A5).**

- FACT: reconnection is left to the library, with 10 attempts and a 5-second maximum delay from the feed's code defaults; the three `live_feed` keys of `config/system_config.yaml` are not passed (A02 K-30, kept) (P01-S091, P01-S092).
- FACT: `_on_close` marks the feed disconnected and stamps the time; `_on_error` only logs; `_on_reconnect` counts and logs each attempt and, once per disconnect and outside any `try`, calls the reconnect callback, which `main.py` sets to `candle_store.mark_reconnect` and then `smart_tgt.on_reconnect`. At an attempt after a gap of more than 600 s it calls the critical-failure callback. INTERPRETATION: the reconnect callback therefore fires at the first attempt, before any reconnection has succeeded, and once an outage passes 600 s every further attempt calls the critical-failure callback again (P01-S059 to P01-S061, P01-S063, P01-S064).
- FACT: when attempts run out, `_on_noreconnect` marks the feed disconnected. In market hours (or when the market check raises) it logs CRITICAL, calls the critical-failure callback and records the feed's own "WebSocket DEAD" alert, which ends as a "suppressed" record because no notifier is set; outside market hours it logs one WARNING. It has no once-only guard (P01-S065 to P01-S068, P01-S150).
- INTERPRETATION: after that, nothing in the feed connects again; unless the library reconnects by itself (nothing in the published library starts a new cycle; Twisted's behaviour past the limit is UNKNOWN / NOT ESTABLISHED), recovery needs a new process (P01-S073).
- FACT: the watchdog runs every 10 s. It always checks the consumer thread; its tick-age check is armed only after the first non-empty batch, and then acts only while connected and inside the entry window (if the window check raises, it proceeds as if inside the window). After 30 s without a batch it logs CRITICAL once per episode, calls the critical-failure callback and sets a flag on which the consumer calls `ticker.close()` (P01-S077 to P01-S080, P01-S083). INTERPRETATION: the feed expects the library to reconnect after that close; whether it does is Twisted's behaviour, UNKNOWN / NOT ESTABLISHED, and if it does not, the watchdog falls silent while disconnected (P01-S083, P01-S084; section 4).
- FACT: the only other health reading is `is_connected()`, which `main.py` reports to the health server without gating; the tick age and the reconnect count are exposed nowhere (P01-S075, P01-S087). At shutdown `_shutdown` calls `disconnect()` once, which closes the ticker and joins only the watchdog (P01-S023, P01-S028, P01-S139).

**Queues, threads and back-pressure (A6).**

- FACT: the feed starts three kinds of daemon thread (the consumer, the watchdog and a restarted consumer); the library's reactor thread is a fourth (P01-S014). The queue holds 10,000 ticks and `_on_ticks` never waits on it (P01-S013). When it is full, the feed logs two CRITICAL lines for each new tick, makes no kill-switch call (none is wired) and drops the new tick if a second put also fails; the docstring and the decision LF5 say the oldest tick is dropped (HISTORICAL) (P01-S044 to P01-S046).
- INTERPRETATION: the consumer dispatches ticks in queue order, in batches with no size limit, and runs every callback on the consumer thread, so a slow callback delays later dispatches and lets the queue fill (P01-S047, P01-S051). Several flags shared between threads are written without a lock (P01-S105).

**Failure, timeout, retry and recovery outcomes (A7).**

- FACT: the feed's own kill-switch calls (queue full, reconnects exhausted, consumer restart failure) and its notifier are not wired by `main.py`. `_make_critical_failure_cb` calls `soft_kill` and, with a notifier, sends a CRITICAL notification; the feed's three reason texts never contain "BrokerAuthError" (P01-S069, P01-S070, P01-S071). INTERPRETATION: only three paths therefore reach the kill switch and the operator: a gap over 600 s at a reconnect attempt, reconnects exhausted in market hours (or when the market check raised), and the tick-age watchdog; `_mark_auth_failed()` cannot be reached from the feed (P01-S070, P01-S071).
- INTERPRETATION: the feed has no authentication-specific branch; a refused key or token could show only as closes, errors and reconnect attempts or, on a silent open socket, as the tick-age alarm (P01-S072). A dead consumer is restarted at each watchdog interval without limit and without notification; nothing supervises the watchdog itself (P01-S085, P01-S086). Exceptions escaping the feed's callbacks go back to the library, whose handling is UNKNOWN / NOT ESTABLISHED (P01-S074).

**What the feed publishes, to whom, in what order (A8).**

- FACT: the feed publishes lists of the six-key dictionaries to its registered callbacks only, in registration order, each call in its own `try`; it keeps no copy and publishes nothing to the event bus, a table or a file. In non-test code there are at most two callbacks: `_tick_dispatcher`, registered at boot, and the placer's `_on_ltp_tick_for_retry`, registered at the first exit retry (A10) (P01-S050, P01-S052, P01-S057).
- INTERPRETATION: callbacks are isolated from one another but ticks are not: if `candle_store.on_tick` or `shadow_tracker.on_tick` raises, `_tick_dispatcher` loses the rest of that batch (A01 C37 (f)) (P01-S056, P01-S119). The registry's identity test cannot match a bound method, which matters only for a bound method registered twice or unregistered; the placer guards its own registration (P01-S053).

**The ticker: construction, connection, subscriptions and callbacks.**

- FACT: `KiteTicker` defaults to 50 reconnect attempts (at most 300), a 60-second maximum reconnect delay (at least 5), a 30-second connect timeout and `wss://ws.kite.trade`; its `reconnect` parameter is accepted but never read. The feed passes 10 attempts and a 5-second maximum delay, which is the library's minimum (P02-S085).

- FACT: `subscribe`, `unsubscribe` and `set_mode` each send one JSON message, with no batching and no size limit, and keep the library's own record of tokens and modes; if the send raises, the method closes the connection and re-raises. On every open after the first, the library resubscribes its whole record (P02-S028, P02-S030). INTERPRETATION: on a reconnect with tracked tokens, the feed's `_on_connect` and the library both send subscribe and mode messages for the same tokens, both asking for LTP (P02-S033, P02-S089). - FACT: every user callback is called directly, with no `try` around it and with the ticker object as its first argument; `on_reconnect` is called before each retry after a failed or lost connection (when the retry count is above 0), and `on_noreconnect` after every retry whenever the retry count exceeds the maximum (P02-S031, P02-S035, P02-S036). INTERPRETATION: the library does not ensure a single `on_noreconnect`; with `debug` off it neither stops the reactor nor ends its thread then; within the library only a new `connect()` starts a new connection cycle (P02-S037).
- FACT: `close()` calls `stop_retry()`, which calls the factory's `stopTrying()`, before it sends the close frame. INTERPRETATION: the library's `close()` is written as a final close, not as a reconnect trigger; whether a retry follows it is Twisted's behaviour, UNKNOWN / NOT ESTABLISHED. The feed's comments expect a reconnect after it (P02-S024, P02-S025, P02-S086).
- FACT: liveness: the library sends no ping frame; its pong check can drop a connection only after a pong has been seen on it; it keeps no time of the last tick and has no no-data timeout; it has no queue of its own between the socket and `on_ticks` (P02-S034, P02-S038 to P02-S040).

**The packets, the LTP tick and tick time stamps (A3, B2).**

- FACT: the binary parser chooses each packet's keys by its length (8, 28, 32, 44 or 184 bytes), not by the mode subscribed; other lengths are skipped silently (P02-S046). An 8-byte LTP packet yields exactly `tradable`, `mode`, `instrument_token` and `last_price`: no time stamp of any kind and no volume (P02-S050).
- FACT: prices are divided by a divisor chosen from the token's segment byte (100 for NSE and most segments) and come out as floats; quantities and volumes stay integers (P02-S045, P02-S048). Only full-mode packets carry `exchange_timestamp` (and 184-byte packets `last_trade_time`), made with `datetime.fromtimestamp(...)` and no zone; no tick of any mode has a key named `timestamp` (P02-S049). INTERPRETATION: such a full-mode time is a naive value in the host's local time zone (P02-S049).
- INTERPRETATION: so for every LTP packet the feed's normalised `timestamp` and `volume` are None (section 3) (P02-S090, P02-S098). What the server sent in the legacy period is UNKNOWN / NOT ESTABLISHED. No token is subscribed at boot. A later subscription depends on the exit-retry path. Whether that path ever ran in production is UNKNOWN / NOT ESTABLISHED (P02-S098). A frame shorter than its declared lengths can raise `struct.error` inside the parser, uncaught, or be parsed under a wrong layout when a short slice happens to have a handled length (P02-S044).

**Threading (A6; A01 W-24, library side).**

- INTERPRETATION: the user callbacks run on the library's reactor thread; the library makes no hand-off to that thread, so the feed's `subscribe` and `close` calls run on whichever thread makes them (the consumer thread, the shutdown caller, or the exit-retry caller). Whether autobahn and Twisted accept calls from other threads is UNKNOWN / NOT ESTABLISHED (P02-S034, P02-S088). The identity the feed stores as `_ticker_thread_id` is its consumer thread's, not the reactor thread's (P02-S087).
- INTERPRETATION (A01 W-24): the library starts one daemon reactor thread at the feed's single `connect()`, never joins it, and `close()` does not end it; no A05 code calls the ticker's `stop()` (P02-S095).

**The REST client methods that A05 code calls (C2 to C4, D1, I3).**

- FACT: A05 code calls `historical_data` (the `main.py` closure and the daily candles script), `instruments("NSE")` (the daily candles script and the instrument refresh) and `profile()` (the daily candles script); no A05 file calls `quote`, `ltp` or `ohlc` (A04's) (P02-S052, P02-S055).
- FACT: a `KiteConnect` built with the API key alone has a 7-second timeout and one plain `requests.Session`; the scripts build theirs that way, while the trading process's Live client is A04's (configured read timeout, mounted connection pool) (P02-S054, P02-S056, P02-S094).
- FACT: every request is one attempt, with no retry, back-off, pacing or HTTP 429 handling; transport errors reach the caller as `requests` exceptions; a response is classified by its `Content-Type`, and an error body's exception class is chosen by the server's `error_type` (P02-S058 to P02-S061).
- FACT: `historical_data` sends one request for the whole range, with no splitting, paging or check of the interval, the dates or the range; it formats a `datetime` without its offset (an aware value's wall-clock digits are sent as they are) and passes any other date type unchanged (P02-S063, P02-S064).
- FACT and INTERPRETATION: each row's `date` is parsed with `dateutil`, so it is aware when the server's string carries an offset and naive otherwise; prices and volume are not converted; rows are not sorted, de-duplicated or checked; one malformed row ends the whole call (P02-S065, P02-S066).
- FACT: `instruments` sends one request and parses the CSV dump in one pass; it converts `instrument_token` and `lot_size` to integers, `last_price`, `strike` and `tick_size` to floats and a 10-character `expiry` to a date, leaves every other column as text, and does not de-duplicate (P02-S067, P02-S068). INTERPRETATION: the whole body is held in memory, not streamed; one bad row ends the call; the callers' dictionaries keep the last row per `tradingsymbol` (P02-S067, P02-S069, P02-S093).

**Current external context (Kite Connect v3 documentation, read 14-Nov-2026; not facts about the legacy period).**

The page types fields as signed integers, while the library reads them unsigned (P02-S099).

## 5. The candle store and live one-minute candles (questions B1 to B5, B7 and B8, live side)

**The component and its interval (B1).**

- FACT: one `CandleStore` is built in `main.py` with `candle_interval_sec=60`, a literal, with no mode condition; no configuration key sets the interval (P03-S062, P03-S063). A later subscription depends on the exit-retry path. Whether that path ever ran in production is UNKNOWN / NOT ESTABLISHED (P03-S101, P03-S127).

**Open, high, low, close and volume; synthetic and partial candles (B3).**

- FACT and INTERPRETATION: for each token and interval, the open is the first price routed to the store, the high and low the extremes, the close the last, all in the order of the `on_tick` calls, not in exchange-time order; the volume is the sum of the `volume` arguments, treated as per-tick increments (P03-S014, P03-S015). The `ts` argument of `on_tick` is not used, and the stored `window_start` and `tick_count` are never read (P03-S016, P03-S029).
- INTERPRETATION: for LTP ticks the dispatcher passes a volume of 0, so every real candle built from them has volume 0 (P03-S066). If quote or full packets were ever received, the dispatcher would pass the library's `volume_traded`, which the current vendor page calls "Volume traded for the day" (current external context, read 14-Nov-2026), and the store would add it up per tick; the code never requests those modes (P03-S072).
- FACT: at each close, every mapped token that had no tick but already has history gets a synthetic flat candle (open, high, low and close equal to the previous close, volume 0, `is_synthetic` True). INTERPRETATION: a token's first candle in a process is always real; synthetic candles chain without limit, and the store has no session or market-hours check, so they continue every minute until `stop()` (P03-S040, P03-S041, P03-S103).
- FACT: a WARNING is logged at the third close in a row with only synthetic candles and at every multiple of 30. INTERPRETATION: it never fires for a feed that has never delivered a tick, nor for one silent token among ticking ones (P03-S042, P03-S043, P03-S126).

**The time stamp convention (B2).**

- FACT: the timer recomputes the next boundary from `time.time()` before every wait and closes when the wait ends (P03-S035). INTERPRETATION (arithmetic): with the 60-second interval the boundaries fall on IST minute boundaries (P03-S036). It does not check that the boundary was reached and keeps no record of the last boundary closed (P03-S037).
- INTERPRETATION: a close that runs late stamps its candles late, a close that overruns the interval merges two minutes into one candle, and a wake before the boundary splits a minute in two; whether any of these occurred is UNKNOWN / NOT ESTABLISHED (P03-S037).
- INTERPRETATION: every candle of one close, real or synthetic, carries the same `ts`: `now_ist()` read once at the start of the close, an aware time at +05:30 a little after the boundary that ends the interval. It is an end-of-interval (close-time) stamp from the host clock, with seconds and microseconds kept, and it is neither an exchange time nor a receipt time. The host's time-zone setting does not affect it (P03-S038, P03-S039, P03-S045).
- INTERPRETATION: which candle a tick joins depends only on whether its `on_tick` call takes the store's lock before or after the close's snapshot; a tick received before a boundary but still waiting in the feed's queue joins the next candle (P03-S031).

**Gaps, duplicates, late and out-of-order ticks; reconnect (B4).**

- INTERPRETATION: the store does nothing about duplicate, late or out-of-order ticks: a repeated tick is applied again, with its volume, and an out-of-order last tick becomes the close. It validates nothing; a token missing from the map still gets a real candle, with `str(token)` as its symbol (P03-S032, P03-S033).
- FACT and INTERPRETATION: `mark_reconnect`, called at the feed's first reconnect attempt, discards the open accumulators. The token's next candle may then cover only part of its interval, and it is not marked; the minutes of the gap become synthetic candles for tokens with history; nothing is refilled from any other source (P03-S055 to P03-S057, P03-S105).

**When a candle is final (B5).**

- FACT and INTERPRETATION: a candle is final when its close emits it: the record is frozen, appended once to the history and passed once to each callback; the store has no path to revise, correct or re-emit it, and a late tick goes into the next candle (P03-S108). `stop()` sets an event without joining the timer and drops the candles being built, apart from one narrow case (P03-S022).
- FACT and INTERPRETATION: history lives only in memory, at most 500 candles per token, synthetic ones included, so a long synthetic run can push out every real candle; a new process starts with none and never reads stored rows back (P03-S020, P03-S047, P03-S103, P03-S106).

**Rounding, price precision and tick size (B7).**

- FACT: the store does no rounding, no tick-size snapping and no price check (sign, zero, finiteness); prices stay the floats it is given (P03-S017). Tick rounding of prices derived from candles happens downstream, for example in the smart-target trail through A04's tick helpers (A04 CG-27; A11's use) (P03-S018).

**Callers and consumers (B8; each consumer's use is its owner's).**

- FACT: the close callbacks run on the timer thread, for each candle, in registration order, each call in its own `try` that logs ERROR with no traceback requested: the smart-target manager's `_on_candle_close` (A11); the structure-exit manager's `on_1m_close` (A11), only when `structure_exit.structure_exit_enabled` is true (committed value `false`; effective value UNKNOWN); then `_persist_candle` (P03-S048, P03-S071, P03-S085).
- FACT: the smart-target manager selects trades by `instrument_token` and reads `high` or `low`, and on a reconnect reads the last 390 candles through `get_candles`, synthetic ones included (P03-S088, P03-S089). The shadow tracker takes ticks, not candles; `BreakevenManager` and `SlBreachMonitor` are not wired (P03-S091, P03-S092). No in-memory consumer reads `is_synthetic` (P03-S094).
- FACT: `_persist_candle` makes one `insert_candle` call (`INSERT OR IGNORE`) per candle per close into the `candles` table in `analytics.db`, on the timer thread, passing `ts` as `candle.ts.isoformat()`; a failing insert is logged at DEBUG, a row skipped by `OR IGNORE` is not logged at all, and the writer is never unregistered (P03-S069, P03-S073, P03-S076, P03-S078, P03-S083). INTERPRETATION (`isoformat` semantics): the text is `YYYY-MM-DDTHH:MM:SS.ffffff+05:30`, the fraction omitted when it is zero (P03-S079). - INTERPRETATION: in meaning the live `ts` agrees with the schema comment "candle close"; in text form it differs from the naive form of the other writers (A03 Y-06, kept); the storage format is A03's and the meaning of the time is A05's (section 11) (P03-S077, P03-S079, P03-S098). Whether any live-written row ever existed is UNKNOWN / NOT ESTABLISHED (P03-S120).

**Threads, locks and failure paths.**

- FACT and INTERPRETATION: one lock guards the store's state; the threads that enter it are the feed's consumer (`on_tick`), the store's own daemon timer (closes and every callback), the library's thread (`mark_reconnect`) and the main thread; the store has no queue and no back-pressure of its own (P03-S058, P03-S059). Once a minute the lock is held while every mapped token is scanned, and the map holds every cached instrument (P03-S025, P03-S060).
- INTERPRETATION: the timer loop has no `try`, no health check and no restart; if it ended, ticks would keep accumulating with no close and no candle would be emitted (P03-S023, P03-S050). The token map stays the boot copy and token history is never removed, because the `gc_sweep` clean-up chain is unwired (A01 C29 (f), kept) (P03-S025, P03-S027, P03-S095).

- FACT: `session_vwap`: the sum of typical price ((high + low + close) / 3) times volume over the sum of volume, for candles with positive volume only, or None; it reads no time, so its "session" scope rests on the caller (P04-S027, P04-S028).
- FACT: `ema_series` and `ema`: factor `2 / (period + 1)`, seeded with the simple mean of the first `period` values (P04-S030, P04-S031). `adx` (period 14 by default) needs `2 × period + 1` candles and uses Wilder smoothing; its docstring says it reuses `true_range_series`, but it computes the same true range inline (P04-S033 to P04-S038). `rsi` (period 14 by default) uses Wilder averages, giving 100 when there are gains and no losses and 50 for a flat series (P04-S040 to P04-S042).
- INTERPRETATION: for a period of 2 or more, the Wilder ATR, the EMA, the ADX and the RSI depend on the whole input, because the seed is taken at its start; the same instrument and period give different values for different lookback lengths or start dates (P04-S025, P04-S032, P04-S039, P04-S043).
- FACT: `resample(base_candles, target_tf, session_bounds)`: `target_tf` is `"day"`/`"daily"` or a positive number of minutes (a broker name such as `"5minute"` raises `ValueError`); the session bounds are injected by the caller, and only candles in `[open, close)` are kept; intraday buckets are anchored at each date's session open and never span dates; each output bar's `ts` is its bucket start (for a daily bar, the session open); "partial" flags only a bucket that overruns the session close, and empty in-session slots are reported, never filled (P04-S045 to P04-S055). **The load and what it lets through (D3, D4).**

- FACT: `load(path)` is a classmethod. It tests `path.exists()` outside any `try`, opens the file with UTF-8 and reads it with `csv.DictReader`; it refuses a file with no header or with a required column missing (order and extra columns are not checked); it converts each row (`int` for the token and the lot size, `float` for the tick, `is_fno` true only for "true", "1" or "yes" in any case), strips only `symbol`, `exchange`, `is_fno` and `sector`, and normalises nothing else (P05-S019 to P05-S024).
- FACT: after conversion three checks refuse a row: an empty symbol, a lot size below 1 and a tick of 0 or below. Nothing else is checked: not the token's value (0 and negative tokens are accepted), not `exchange` (any text), not `sector`, not the symbol's characters or case, not repeated symbols or tokens, and not the number of rows (P05-S028). INTERPRETATION (conversion and floating-point semantics): unrecognised `is_fno` text silently becomes False, and a `nan` or `inf` tick passes the check (P05-S025, P05-S029).
- FACT: the first problem found ends the load; no row is skipped and no partial cache is returned; a header-only file loads as an empty cache with no error (P05-S032).
- FACT and INTERPRETATION (as marked in the evidence table): the exception for each file problem: an absent file gives `ConfigMissingError` ("not found"); a directory, an unreadable file or bytes that are not UTF-8 give `ConfigMissingError` ("Could not read"); a missing header, a missing column (also a byte-order mark before `symbol`, or a header name in another case), a value that does not convert and the three refused values give `ConfigSchemaError` with a line number; a row with fewer fields than the header gives an unwrapped `TypeError` or `AttributeError`; a reader error gives an unwrapped `csv.Error`; and an `exists()` failure other than "not found" leaves as that `OSError`, unwrapped (P05-S020, P05-S027, P05-S030, P05-S031, P05-S034). HISTORICAL: the docstring and the module's decision IC12 name only `ConfigMissingError` and `ConfigSchemaError` (P05-S010, P05-S019). The tests use none of the edge cases above (P05-S097).

**Keys, duplicates and accessors (D3, I1).**

- INTERPRETATION (dictionary semantics): the two indexes are built by comprehension, so for a repeated symbol or token the later row wins, with no notice; `all_rows()` and `count()` include every row, duplicates and token-0 rows included; `token_map()` is built from all rows (P05-S016, P05-S017, P05-S046).
- FACT: `get_by_symbol` and `get_by_token` return a row or raise `InstrumentNotFoundError` (derived from `TradingSystemError`, not from `KeyError`), never None; `lot_size` and `tick_size` raise in the same way; `sector` returns "UNKNOWN" for a missing symbol or a blank cell and raises nothing; every lookup is exact and case-sensitive, while the load stripped the stored symbol (P05-S041 to P05-S047). There is no `is_fno` accessor, no per-exchange or F&O selection and no method that reports the file's age; `is_fno` and `exchange` are reachable only through a row (P05-S048).
