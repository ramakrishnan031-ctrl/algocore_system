## Part A — Study findings (reconciled)

## 3. Market data in brief

From STUDY 2, with the AUDIT's refinements applied.

The trading process (one per start) loads the instrument master `config/instruments.csv` once at boot into one `InstrumentCache`, which every consumer receives; nothing reloads it, so a refreshed file reaches the process only at its next start. One `LiveFeedManager` opens one `KiteTicker` WebSocket and asks only for LTP mode; each tick becomes a six-key dictionary, passes through a bounded queue to one consumer thread and is dispatched to `_tick_dispatcher` (the candle store, then the shadow tracker, A11) and, once an exit retry has registered it, to the order placer's callback (A10). No token is subscribed at boot. A later subscription depends on the exit-retry path. Whether that path ever ran in production is UNKNOWN / NOT ESTABLISHED. The candle store builds one-minute candles by the host clock, real ones from the LTPs it is given and synthetic flat ones for silent tokens that already have history; it keeps the last 500 per token in memory and hands each closed candle to the smart-target manager, the structure-exit manager (only when its switch is on; committed value off) and `_persist_candle`, which inserts it into the `candles` table.

Historical candles reach the trading process through one closure over the live REST client and the limiter's `historical` bucket, built once at boot when any of six feature flags is on (three are, at the committed values); six consumers use it, each through its own `OhlcFetcher` with an in-memory cache (A08 and A18), and nothing on this path is stored. `core/candle_math.py` holds eight pure functions; its 14 non-test calls, in six modules owned by A08, A15 and A18, all work on broker historical candles, and `resample` has no non-test caller.

Outside the trading process four scripts run, each in its own process (the refresh and the daily candles script each with its own broker client; the ban-list script and the alias tool with none): `scripts/refresh_instruments.py` (declared 09:00 Monday to Friday, and also launched by a pre-flight auto-fix) joins tracked reference files with the broker's NSE instrument dump and rewrites `config/instruments.csv`; `scripts/fetch_daily_candles.py` (declared 15:40) writes one-minute candles of the configured indices and the day's traded symbols to `candles` and, for the traded symbols only, to a candle CSV; `scripts/fetch_fno_ban.py` (declared 08:35) reads the NSE archive's ban file into the `fno_ban` table, which no non-test code reads; `scripts/find_symbol_aliases.py` prints alias candidates, and the alias file is edited by hand. The declarations are A16's and are not evidence of runs. The `candles` table can hold rows from three kinds of writer, with no column naming the source and with different timestamp forms. Nothing here says what ran in production: every runtime fact is UNKNOWN / NOT ESTABLISHED (STUDY 1.6).

### 4.1 The live feed and tick intake (STUDY 3)
