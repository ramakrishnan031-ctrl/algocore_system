## 3. True range and ATR: `true_range_series` and `atr`

P04-S018. FACT (L54 to L80): `true_range_series(candles: Sequence["Candle"]) -> List[float]`. For each candle, in input order, it takes `high = float(c.high)` and `low = float(c.low)` (L72 to L73). For the first candle, `TR_0 = high - low` (L74 to L75). For every later candle, `TR_t = max(high_t - low_t, |high_t - close_(t-1)|, |low_t - close_(t-1)|)` (L76 to L77), where `close_(t-1)` is `float(close)` of the previous element of the input (L79). It returns a list of the same length as the input, and `[]` for an empty input (L69, L80). It does not sort, does not read `ts`, and does not check order, duplicates or gaps.

P04-S019. HISTORICAL (L61 to L62, docstring): the first value is "a degenerate "range", not a true range — atr() excludes it". HISTORICAL (L66 to L67): "Candles are processed in the given order and never re-sorted (caller supplies chronological order)."

P04-S020. INTERPRETATION (Python semantics, L72 to L79): the "previous close" is the previous list element, whatever time separates the two candles; a missing bar, a session break or a day break is not detected. The first value is negative if a candle has `high < low`; every later value is non-negative, because two of the three terms are absolute values. A `None` in `high`, `low` or `close` raises `TypeError` (from `float(None)`); a numeric string is converted silently by `float`.

P04-S021. FACT (L83 to L113): `atr(candles, period, method=ATR_WILDER) -> Optional[float]`. It raises `ValueError` when `period` is not an `int`, is a `bool`, or is not positive (L108 to L109), and when `method` is not exactly `"wilder"` or `"sma"` (L110 to L113; a case-sensitive comparison). `period` has no default.

P04-S022. FACT (L114 to L118): when `len(candles) < period + 1` it returns `None` (L114 to L115). Otherwise it computes `true_range_series(candles)` and drops the first value: `real = trs[1:]` (L117 to L118), so `len(real) = len(candles) - 1 >= period`.

P04-S023. FACT (L121 to L123): `method="sma"` returns `sum(real[-period:]) / period`, the plain mean of the last `period` true ranges.

P04-S024. FACT (L125 to L129): `method="wilder"` (the default) seeds `ATR = sum(real[:period]) / period` (the mean of the first `period` true ranges, L126), then for each later true range applies `ATR = (ATR * (period - 1) + TR) / period` (L127 to L128), and returns the final value (L129). HISTORICAL (L96 to L98): "Seed = mean of the first ``period`` prev-close true ranges; then ``ATR_t = (ATR_{t-1} * (period - 1) + TR_t) / period``." The docstring and the code agree.

P04-S025. FACT (L117 to L129): the result is a Python `float` at full precision; nothing is rounded. INTERPRETATION (the formula): it is in the price units of the candles (a mean of price differences). The `"sma"` value depends only on the last `period + 1` candles. The `"wilder"` value depends on every candle passed, because the seed is taken at the start of the input and each later candle enters the recursion; the same instrument and period give different values for different lookback lengths or start dates, and the effect of the seed decays geometrically by `(period - 1) / period` per later candle.

P04-S026. INTERPRETATION (Python semantics, L114): `len(candles)` requires a sized sequence; a generator raises `TypeError`. A non-numeric value raises in `true_range_series` (P04-S020). Nothing in `atr` catches an exception; error handling is the caller's (section 10).

## 4. Volume-weighted average price: `session_vwap`

P04-S027. FACT (L136 to L158): `session_vwap(candles) -> Optional[float]`. For each candle it takes `v = float(c.volume)` (L150) and skips the candle when `v <= 0.0` (L151 to L152). Otherwise it adds `typical * v` to a numerator and `v` to a denominator, with `typical = (float(high) + float(low) + float(close)) / 3.0` (L153 to L155). It returns `None` when the total volume is not positive (L156 to L157), which covers an empty input and an input whose volumes are all zero or negative; otherwise it returns `numerator / denominator` (L158). Formula: VWAP = Σ(((high + low + close) / 3) × volume) / Σ(volume), over the candles with positive volume.

P04-S028. FACT (L149 to L158): the function reads no `ts` and no `open`, and filters nothing by date or time; the word "session" in its name is not enforced by the code. HISTORICAL (L142 to L144, docstring): "The caller scopes `candles` to the intended session/window (e.g. today's in-session bars) — this function is a pure reducer over whatever it is given". The one non-test caller scopes the candles itself (section 10, call 9).

P04-S029. INTERPRETATION (the formula): the value is a typical-price approximation per bar, weighted by bar volume; it is not the exchange's average traded price. A candle with a negative volume is skipped, not rejected. Nothing is rounded; the result is in the candles' price units. A `None` volume raises `TypeError` (from `float(None)`, L150); a `None` price raises only on a candle with positive volume, because the prices of a skipped candle are not read (L151 to L153).

## 5. Exponential moving average: `ema_series` and `ema`

P04-S030. FACT (L165 to L181): `ema_series(values: Sequence[float], period: int) -> List[float]` takes plain numbers, not candles. It raises `ValueError` for a `period` that is not an `int`, is a `bool`, or is not positive (L171 to L172). It converts every value with `float` (L173) and returns `[]` when there are fewer values than `period` (L174 to L175). Otherwise: smoothing factor `k = 2 / (period + 1)` (L176); seed = `sum(vals[:period]) / period`, the simple mean of the first `period` values (L177); then, for each later value `v`, `EMA_t = v × k + EMA_(t-1) × (1 - k)` (L178 to L180). The list has `len(values) - period + 1` elements; its first element belongs to input index `period - 1`.

P04-S031. FACT (L184 to L188): `ema(values, period) -> Optional[float]` returns the last element of `ema_series(values, period)`, or `None` when that list is empty. It has the same validation (through `ema_series`) and no default period.

P04-S032. INTERPRETATION (Python semantics, L173): `values` can be any iterable of numbers or numeric strings; `None` raises `TypeError`. As with the Wilder ATR (P04-S025), the result depends on the whole input, because the seed is taken at the start; the seed's weight decays by `(1 - k)` per later value. Nothing is rounded. Every non-test caller passes candle closes (section 10).

## 6. Average directional index: `adx` and its inner `_wilder`

P04-S033. FACT (L191 to L202): `adx(candles, period: int = 14) -> Optional[float]`. It raises `ValueError` for an invalid `period` (same rule as `atr`, L198 to L199) and returns `None` when `len(candles) < 2 × period + 1` (L200 to L202). HISTORICAL (L192 to L194): "Requires at least ``2*period + 1`` candles so the DX series is long enough to seed + smooth the ADX."

P04-S034. FACT (L204 to L217): for each candle `i` from the second onwards, with `prev` the previous list element: `up = high_i - high_(i-1)` and `dn = low_(i-1) - low_i` (L209 to L210); `+DM_i = up` if `up > dn` and `up > 0`, else `0.0` (L211); `-DM_i = dn` if `dn > up` and `dn > 0`, else `0.0` (L212); `TR_i = max(high_i - low_i, |high_i - close_(i-1)|, |low_i - close_(i-1)|)` (L213 to L217). Each of the three lists has `len(candles) - 1` elements. When `up` equals `dn`, both directional movements are `0.0` (strict comparisons).

P04-S035. HISTORICAL (L194 to L195): "Uses true_range_series for TR (reuse, no duplication)." FACT (L213 to L217; the only call of `true_range_series` in the module is at L117, inside `atr`): `adx` does not call `true_range_series`; it computes the true range inline. INTERPRETATION (comparison of L77 with L213 to L217): the inline expression is the same formula as `true_range_series` uses for every candle after the first, so `adx`'s true ranges equal `true_range_series(candles)[1:]`; the difference is in the reuse claim only.

P04-S036. FACT (L219 to L227): the inner `_wilder(x)` returns a running Wilder total, not an average: `S_0 = sum(x[:period])` (L220 to L221), then `S_t = S_(t-1) - S_(t-1) / period + x_t` for each later element (L222 to L224); it returns `len(x) - period + 1` values. It is applied to `+DM`, `-DM` and `TR` (L227). INTERPRETATION (algebra): dividing by `period` gives the average-form recursion `A_t = A_(t-1) × (period - 1) / period + x_t / period`, so the ratios formed next are the same as with Wilder averages.

P04-S037. FACT (L228 to L236): for each triple of smoothed values: if the smoothed `TR <= 0.0`, `DX = 0.0` (L230 to L232); otherwise `+DI = 100 × S(+DM) / S(TR)`, `-DI = 100 × S(-DM) / S(TR)` (L233 to L234), and `DX = 100 × |+DI - -DI| / (+DI + -DI)` when the sum is positive, else `0.0` (L235 to L236).

P04-S038. FACT (L238 to L243): if fewer than `period` DX values exist it returns `None` (L238 to L239); otherwise `ADX` is seeded with the mean of the first `period` DX values (L240) and smoothed with `ADX = (ADX × (period - 1) + DX) / period` over the remaining DX values (L241 to L242); the final value is returned (L243), unrounded. INTERPRETATION (arithmetic on P04-S033, P04-S034, P04-S036): with `n >= 2 × period + 1` candles there are `n - period >= period + 1` DX values, so the check at L238 cannot be true when it is reached; with exactly `2 × period + 1` candles one smoothing step follows the seed.

P04-S039. INTERPRETATION (the formula): each DX lies between 0 and 100 because both directional movements are non-negative, so the ADX, a weighted mean of DX values, lies between 0 and 100; it is dimensionless. Like the Wilder ATR, it depends on every candle passed (P04-S025). A window in which every true range is zero (flat prices with no gaps) gives smoothed `TR = 0` and `DX = 0.0` (L230 to L232), not an error.

## 7. Relative strength index: `rsi`

P04-S040. FACT (L250 to L269): `rsi(candles, period: int = 14) -> Optional[float]`. It raises `ValueError` for an invalid `period` (L266 to L267) and returns `None` when `len(candles) < period + 1` (L268 to L269). It reads only `close` (L271).

P04-S041. FACT (L271 to L285): `closes = [float(close) ...]`; for each consecutive pair, `delta = close_i - close_(i-1)`, `gain = delta` if `delta > 0` else `0.0`, `loss = -delta` if `delta < 0` else `0.0` (L274 to L277). Seeds: `avg_gain = sum(gains[:period]) / period`, `avg_loss = sum(losses[:period]) / period` (L280 to L281). Wilder smoothing over the remaining deltas: `avg = (avg × (period - 1) + value) / period` for gains and for losses (L283 to L285).

P04-S042. FACT (L287 to L290): if `avg_loss == 0.0` it returns `100.0` when `avg_gain > 0.0`, else `50.0`; otherwise `RS = avg_gain / avg_loss` and `RSI = 100 - 100 / (1 + RS)`. The value is returned unrounded. HISTORICAL (L256 to L261, docstring): the same seed, recursion and formula, "When the window has NO losses, RSI is 100.0 (maximally overbought); a perfectly flat series (no gains, no losses) returns the neutral 50.0." The docstring and the code agree.

P04-S043. INTERPRETATION (the formula and floating-point arithmetic): the result is dimensionless, between 0 and 100. It depends on every candle passed (the seed is the first `period` deltas). `avg_loss` is exactly `0.0` only when no delta in the whole input was negative, because the recursion keeps a positive average positive (short of floating-point underflow over a very long input). Any time gap between consecutive candles (a missing bar or day) is not detected; the delta is taken between consecutive list elements.

P04-S046. FACT (L335 to L339, L376 to L383): `resample(base_candles, target_tf, session_bounds) -> ResampleResult`. INTERPRETATION (L378 to L383): any other string, including a broker interval name such as `"5minute"`, raises `ValueError`; the integer has no upper bound and is not checked against the base candles' timeframe, which the function is not told (it has no base-timeframe parameter).

P04-S047. FACT (L385 to L386): the inner `_bounds_for(d)` returns `session_bounds(d)` when `session_bounds` is callable, otherwise `session_bounds` itself. The returned pair is not checked.

P04-S048. FACT (L389 to L402): for each base candle, in input order: `ts = cd.ts` (L394); while `tz` is `None` it takes `ts.tzinfo` (L395 to L396), so `tz` is the zone of the first candle in input order that has one (this happens before the session test); `d = ts.date()` (L397); `(open_t, close_t) = _bounds_for(d)` (L398); `t = ts.time()` (L399); the candle is skipped when `t < open_t or t >= close_t` (L400 to L401), so only the half-open interval `[open, close)` is kept; for a kept candle the date's bounds are recorded in `dates_seen` (L402). INTERPRETATION (L400): when the injected close is at or before the open, every candle of that date is skipped.

P04-S049. FACT (L404 to L410): `open_dt = datetime.combine(d, open_t, tzinfo=ts.tzinfo)` (L404). Daily: the bucket start is `open_dt` (L405 to L406). Intraday: `mins = (ts - open_dt).total_seconds() / 60.0`, `k = int(mins // target_tf)` and the bucket start is `open_dt + k × target_tf` minutes (L407 to L410). So intraday buckets are anchored at each date's session open and never span dates, and a candle goes to the bucket whose start is at or before its `ts`. HISTORICAL (L349 to L353): "buckets are anchored to each date's SESSION OPEN ... e.g. 30m from a 09:15 open -> 09:15, 09:45, 10:15, ... Intraday buckets NEVER span days ... Base candles outside ``[open, close)`` — pre-open / after-hours — are excluded." The docstring and the code agree.

P04-S050. FACT (L412 to L424): aggregation: the first candle of a bucket in input order sets open, high, low, close and volume (L416 to L417); each later one raises the high if higher (L419 to L420), lowers the low if lower (L421 to L422), replaces the close (L423, commented "last-in-order close") and adds its volume (L424). Prices are taken with `float`, volume with `int(cd.volume)` (L412 to L414).

P04-S051. FACT (L426 to L429): the output bars are `Candle(ts=bucket_start, open=..., high=..., low=..., close=..., volume=...)`, one per non-empty bucket, sorted by bucket start (`sorted(buckets.items())`, L428). HISTORICAL (L367 to L370): "Base candles are assumed chronologically ordered and to share one tzinfo convention (aware IST, or naive IST — matching the Candle contract); order is preserved, not re-sorted." INTERPRETATION (L415 to L428): the bars are sorted, but inside a bucket the open is the first and the close the last candle in input order; an out-of-order input therefore changes the open and the close without any error, and a duplicated base candle is counted twice in the volume (the high and low are unchanged). An empty input gives `bars == []` and two empty tuples.

P04-S052. FACT (L431 to L450): the flags are computed only for intraday resamples (L434). For each date in `dates_seen` (dates with at least one kept candle), in date order: `total_min = (close.hour × 60 + close.minute) - (open.hour × 60 + open.minute)` (L436; seconds ignored); the date is skipped when `total_min <= 0` (L437 to L438); `open_dt` and `close_dt` are built with `tz`, the first candle's zone (L439 to L440); `n_slots = ceil(total_min / target_tf)` (L441); for each slot, `slot_dt = open_dt + k × target_tf`, `slot_end = slot_dt + target_tf` and `is_partial = slot_end > close_dt` (L442 to L445). A slot that has a bucket is recorded in `partial` when it is partial (L446 to L448); a slot without a bucket is recorded in `empty`, partial or not (L449 to L450).

P04-S053. INTERPRETATION (arithmetic on L436 to L445, for a 09:15 to 15:30 session injected by a caller; the module itself holds no session time): 375 minutes give 75 slots at 5 minutes, 25 at 15 minutes, 13 at 30 minutes and 7 at 60 minutes; the last slot is partial at 30 minutes (15:15 to 15:45) and at 60 minutes (15:15 to 16:15); no slot is partial at 5 or 15 minutes. This agrees with the docstring's example (P04-S045).

P04-S054. INTERPRETATION (L441 to L450; question B5): "partial" means only the session-tail overrun. The function does not count the base candles of a bucket, so a bucket that is still forming (base data ending inside it) or that lacks some base candles is emitted as an ordinary bar, unflagged, and `partial_last` is then `False`. For a date whose data stops before the close (for example a call during the session), every later slot of that date is reported in `empty_bucket_starts`. A date with no kept candle reports nothing. The function has no notion of a final candle and cannot revise a bar; each call recomputes from its input.

P04-S055. FACT (L405 to L406, L434, L452 to L456): a daily resample gives one bar per date with kept candles; its `ts` is the session-open datetime of that date (for example 09:15, not midnight), built from the kept candles only. Its `partial_bucket_starts` and `empty_bucket_starts` are always empty, so `partial_last` is always `False`. INTERPRETATION: a daily bar built from part of a session is not distinguished from a full one.

P04-S056. FACT (L391 to L404, L439 to L440): the session test uses each candle's own wall-clock `ts.date()` and `ts.time()` (L397, L399); bucket starts carry the candle's own `tzinfo` (L404); the flag datetimes carry `tz` (L439 to L440). No zone conversion is made. INTERPRETATION (Python semantics: `datetime.time()` returns a naive time): (a) an aware timestamp in another zone (for example UTC) would be tested and bucketed on that zone's wall clock; (b) kept candles that mix naive and aware timestamps make `sorted(buckets.items())` raise `TypeError` (L428); (c) aware `time` values returned by `session_bounds` make the comparison at L400 raise `TypeError`; (d) seconds in a timestamp enter the minutes arithmetic (09:15:30 is 0.5 minutes after a 09:15 open), so a sub-minute timestamp stays in the bucket containing it; (e) `int(cd.volume)` truncates a fractional volume towards zero.

P04-S057. INTERPRETATION (L394, L407 to L410; questions B2 and B6): the result depends on what a base candle's `ts` means. With base candles stamped at their start (as in the tests' fixtures, P04-S082), a 1-minute candle stamped 09:44 goes to the 09:15 bucket of a 30-minute grid. A candle stamped at its close goes one bucket later whenever its close falls on a bucket boundary (the 09:44 to 09:45 candle stamped 09:45 would go to the 09:45 bucket), and the first candle of a session stamped at its close (09:16) would still be kept while a last candle stamped 15:30 would be dropped by the `[open, close)` test. The output `ts` is always the bucket start. Which convention each candle source uses: live `CandleData` (part P03; its field comment says close time, P04-S015); broker rows (section 9).

P04-S058. FACT (L367; L376 to L456): HISTORICAL "Pure and deterministic: no clock, no I/O; output depends only on inputs." The code reads no clock, file, configuration or broker. ## 9. The contract common to all functions (questions B2, B4, B6, B7, I4, I5)

P04-S059. FACT (sections 3 to 8): no function sorts its input or checks its order; `resample` sorts only its output bars (L428). INTERPRETATION: every result depends on the input order (the previous close of the true range; the Wilder recursions of ATR, ADX and RSI; the EMA recursion; `resample`'s open and close), so an input in another order gives different values without an error.
