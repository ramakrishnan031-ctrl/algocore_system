## 3. True range and ATR: `true_range_series` and `atr`

P04-S018. FACT (L54 to L80): `true_range_series(candles: Sequence["Candle"]) -> List[float]`. For each candle, in input order, it takes `high = float(c.high)` and `low = float(c.low)` (L72 to L73). For the first candle, `TR_0 = high - low` (L74 to L75). For every later candle, `TR_t = max(high_t - low_t, |high_t - close_(t-1)|, |low_t - close_(t-1)|)` (L76 to L77), where `close_(t-1)` is `float(close)` of the previous element of the input (L79). It returns a list of the same length as the input, and `[]` for an empty input (L69, L80). It does not sort, does not read `ts`, and does not check order, duplicates or gaps.

P04-S019. HISTORICAL (L61 to L62, docstring): the first value is "a degenerate "range", not a true range — atr() excludes it". HISTORICAL (L66 to L67): "Candles are processed in the given order and never re-sorted (caller supplies chronological order)."

P04-S020. INTERPRETATION (Python semantics, L72 to L79): the "previous close" is the previous list element, whatever time separates the two candles; a missing bar, a session break or a day break is not detected. The first value is negative if the first candle has `high < low`; every later value is non-negative, because two of the three terms are absolute values. Nothing checks that `low <= high` or that the close lies between them. A `None` in `high`, `low` or `close` raises `TypeError` (from `float(None)`); a numeric string is converted silently by `float`.

P04-S021. FACT (L83 to L113): `atr(candles, period, method=ATR_WILDER) -> Optional[float]`. It raises `ValueError` when `period` is not an `int`, is a `bool`, or is not positive (L108 to L109), and when `method` is not exactly `"wilder"` or `"sma"` (L110 to L113; a case-sensitive comparison). `period` has no default.

P04-S022. FACT (L114 to L118): when `len(candles) < period + 1` it returns `None` (L114 to L115). Otherwise it computes `true_range_series(candles)` and drops the first value: `real = trs[1:]` (L117 to L118), so `len(real) = len(candles) - 1 >= period`.

P04-S023. FACT (L121 to L123): `method="sma"` returns `sum(real[-period:]) / period`, the plain mean of the last `period` true ranges.

P04-S024. FACT (L125 to L129): `method="wilder"` (the default) seeds `ATR = sum(real[:period]) / period` (the mean of the first `period` true ranges, L126), then for each later true range applies `ATR = (ATR * (period - 1) + TR) / period` (L127 to L128), and returns the final value (L129). HISTORICAL (L96 to L98): "Seed = mean of the first ``period`` prev-close true ranges; then ``ATR_t = (ATR_{t-1} * (period - 1) + TR_t) / period``." The docstring and the code agree.

P04-S025. FACT (L117 to L129): the result is a Python `float` at full precision; nothing is rounded. INTERPRETATION (the formula): it is in the price units of the candles (a mean of price differences). The `"sma"` value depends only on the last `period + 1` candles. For a `period` of 2 or more, the `"wilder"` value depends on every candle passed, because the seed is taken at the start of the input and each later candle enters the recursion; the same instrument and period give different values for different lookback lengths or start dates, and the effect of the seed decays geometrically by `(period - 1) / period` per later candle. With `period` 1 that factor is 0, and both methods return the last true range.

P04-S026. INTERPRETATION (Python semantics, L114): `len(candles)` requires a sized sequence; a generator raises `TypeError`. A non-numeric value raises in `true_range_series` (P04-S020). Nothing in `atr` catches an exception; error handling is the caller's (section 10).

## 4. Volume-weighted average price: `session_vwap`

P04-S027. FACT (L136 to L158): `session_vwap(candles) -> Optional[float]`. For each candle it takes `v = float(c.volume)` (L150) and skips the candle when `v <= 0.0` (L151 to L152). Otherwise it adds `typical * v` to a numerator and `v` to a denominator, with `typical = (float(high) + float(low) + float(close)) / 3.0` (L153 to L155). It returns `None` when the total volume is not positive (L156 to L157), which covers an empty input and an input whose volumes are all zero or negative; otherwise it returns `numerator / denominator` (L158). Formula: VWAP = Σ(((high + low + close) / 3) × volume) / Σ(volume), over the candles with positive volume.

P04-S028. FACT (L149 to L158): the function reads no `ts` and no `open`, and filters nothing by date or time; the word "session" in its name is not enforced by the code. HISTORICAL (L142 to L144, docstring): "The caller scopes `candles` to the intended session/window (e.g. today's in-session bars) — this function is a pure reducer over whatever it is given". The one non-test caller scopes the candles itself (section 10, call 10).

P04-S029. INTERPRETATION (the formula): the value approximates each bar by its typical price, weighted by bar volume; it is not computed from trades and is not the broker quote's `average_price` (P04-S091). ## 5. Exponential moving average: `ema_series` and `ema`

P04-S030. FACT (L165 to L181): `ema_series(values: Sequence[float], period: int) -> List[float]` takes plain numbers, not candles. It raises `ValueError` for a `period` that is not an `int`, is a `bool`, or is not positive (L171 to L172). It converts every value with `float` (L173) and returns `[]` when there are fewer values than `period` (L174 to L175). Otherwise: smoothing factor `k = 2 / (period + 1)` (L176); seed = `sum(vals[:period]) / period`, the simple mean of the first `period` values (L177); then, for each later value `v`, `EMA_t = v × k + EMA_(t-1) × (1 - k)` (L178 to L180). The list has `len(values) - period + 1` elements; its first element belongs to input index `period - 1`.

P04-S031. FACT (L184 to L188): `ema(values, period) -> Optional[float]` returns the last element of `ema_series(values, period)`, or `None` when that list is empty. It has the same validation (through `ema_series`) and no default period.

P04-S032. INTERPRETATION (Python semantics, L173): `values` can be any iterable of numbers or numeric strings; `None` raises `TypeError`. As with the Wilder ATR (P04-S025), for a `period` of 2 or more the result depends on the whole input, because the seed is taken at the start; the seed's weight decays by `(1 - k)` per later value. With `period` 1, `k` is 1 and `ema` returns the last value. Nothing is rounded. Every non-test caller passes candle closes (section 10).

## 6. Average directional index: `adx` and its inner `_wilder`

P04-S033. FACT (L191 to L202): `adx(candles, period: int = 14) -> Optional[float]`. It raises `ValueError` for an invalid `period` (same rule as `atr`, L198 to L199) and returns `None` when `len(candles) < 2 × period + 1` (L200 to L202). HISTORICAL (L192 to L194): "Requires at least ``2*period + 1`` candles so the DX series is long enough to seed + smooth the ADX."

P04-S034. FACT (L204 to L217): for each candle `i` from the second onwards, with `prev` the previous list element: `up = high_i - high_(i-1)` and `dn = low_(i-1) - low_i` (L209 to L210); `+DM_i = up` if `up > dn` and `up > 0`, else `0.0` (L211); `-DM_i = dn` if `dn > up` and `dn > 0`, else `0.0` (L212); `TR_i = max(high_i - low_i, |high_i - close_(i-1)|, |low_i - close_(i-1)|)` (L213 to L217). Each of the three lists has `len(candles) - 1` elements. When `up` equals `dn`, both directional movements are `0.0` (strict comparisons).

P04-S035. HISTORICAL (L194 to L195): "Uses true_range_series for TR (reuse, no duplication)." FACT (L213 to L217; the only call of `true_range_series` in the module is at L117, inside `atr`): `adx` does not call `true_range_series`; it computes the true range inline. INTERPRETATION (comparison of L77 with L213 to L217): the inline expression is the same formula as `true_range_series` uses for every candle after the first, so `adx`'s true ranges equal `true_range_series(candles)[1:]`; the difference is in the reuse claim only.

P04-S036. FACT (L219 to L227): the inner `_wilder(x)` returns a running Wilder total, not an average: `S_0 = sum(x[:period])` (L220 to L221), then `S_t = S_(t-1) - S_(t-1) / period + x_t` for each later element (L222 to L224); it returns `len(x) - period + 1` values. It is applied to `+DM`, `-DM` and `TR` (L227). INTERPRETATION (algebra): dividing by `period` gives the average-form recursion `A_t = A_(t-1) × (period - 1) / period + x_t / period`, so the ratios formed next are the same as with Wilder averages.

P04-S037. FACT (L228 to L236): for each triple of smoothed values: if the smoothed `TR <= 0.0`, `DX = 0.0` (L230 to L232); otherwise `+DI = 100 × S(+DM) / S(TR)`, `-DI = 100 × S(-DM) / S(TR)` (L233 to L234), and `DX = 100 × |+DI - -DI| / (+DI + -DI)` when the sum is positive, else `0.0` (L235 to L236).

P04-S038. FACT (L238 to L243): if fewer than `period` DX values exist it returns `None` (L238 to L239); otherwise `ADX` is seeded with the mean of the first `period` DX values (L240) and smoothed with `ADX = (ADX × (period - 1) + DX) / period` over the remaining DX values (L241 to L242); the final value is returned (L243), unrounded. INTERPRETATION (arithmetic on P04-S033, P04-S034, P04-S036): with `n >= 2 × period + 1` candles there are `n - period >= period + 1` DX values, so the check at L238 cannot be true when it is reached; with exactly `2 × period + 1` candles one smoothing step follows the seed.

P04-S039. INTERPRETATION (the formula): each DX lies between 0 and 100 because both directional movements are non-negative, so the ADX, a weighted mean of DX values, lies between 0 and 100; it is dimensionless. Like the Wilder ATR, for a `period` of 2 or more it depends on every candle passed (P04-S025); with `period` 1 each smoothed total equals its latest value (L223) and the ADX is the last DX, which comes from the last two candles. A window in which every true range is zero (flat prices with no gaps) gives smoothed `TR = 0` and `DX = 0.0` (L230 to L232), not an error.

## 7. Relative strength index: `rsi`

P04-S040. FACT (L250 to L269): `rsi(candles, period: int = 14) -> Optional[float]`. It raises `ValueError` for an invalid `period` (L266 to L267) and returns `None` when `len(candles) < period + 1` (L268 to L269). It reads only `close` (L271).

P04-S041. FACT (L271 to L285): `closes = [float(close) ...]`; for each consecutive pair, `delta = close_i - close_(i-1)`, `gain = delta` if `delta > 0` else `0.0`, `loss = -delta` if `delta < 0` else `0.0` (L274 to L277). Seeds: `avg_gain = sum(gains[:period]) / period`, `avg_loss = sum(losses[:period]) / period` (L280 to L281). Wilder smoothing over the remaining deltas: `avg = (avg × (period - 1) + value) / period` for gains and for losses (L283 to L285).

P04-S042. FACT (L287 to L290): if `avg_loss == 0.0` it returns `100.0` when `avg_gain > 0.0`, else `50.0`; otherwise `RS = avg_gain / avg_loss` and `RSI = 100 - 100 / (1 + RS)`. The value is returned unrounded. HISTORICAL (L256 to L261, docstring): the same seed, recursion and formula, "When the window has NO losses, RSI is 100.0 (maximally overbought); a perfectly flat series (no gains, no losses) returns the neutral 50.0." The docstring and the code agree.

P04-S043. INTERPRETATION (the formula and floating-point arithmetic): the result is dimensionless, between 0 and 100. For a `period` of 2 or more it depends on every candle passed (the seed is the first `period` deltas), and `avg_loss` is exactly `0.0` only when no delta in the whole input was negative, because the recursion keeps a positive average positive (short of floating-point underflow over a very long input). With `period` 1 both averages are those of the last delta alone, so the RSI is 100.0 after a rise, 0.0 after a fall and 50.0 after an unchanged close. Any time gap between consecutive candles (a missing bar or day) is not detected; the delta is taken between consecutive list elements.

## 15. Points the AUDIT may examine (neutral)

1. The header's purpose, inputs, outputs and "Wiring : NONE yet" lines name two helpers and no wiring, while the file defines eight public functions and six non-test modules import it; the header and the first imports came in the same commit (P04-S007 to P04-S010).
2. `adx`'s docstring and `docs/SYSTEM_MAP.md` say it reuses `true_range_series`; it computes the same true range inline (P04-S035, P04-S085, P04-S090).
3. `DAILY_TF` is defined and never used; `resample` tests a literal tuple (P04-S016).
4. `atr` has no default period ("no default period is baked in here"), while `adx` and `rsi` default to 14 (P04-S016).
5. `session_vwap` reads no time, so its "session" scope rests on the caller; its one caller scopes by wall-clock date and session but not by completeness (P04-S028, P04-S074).
6. No function checks the order of its input, removes duplicates or detects gaps, and nothing in the fetch chain sorts the broker's rows; the order the server sent is UNKNOWN / NOT ESTABLISHED (P04-S059, P04-S060, P04-S067).
7. The Wilder ATR, ADX and RSI and the EMA depend on the length and start of the input, and the callers fetch different windows (90 calendar days of daily candles; 400 days of index daily candles; 10 days of 30-minute candles; 180-day structure windows), so the same indicator and period can give different values on different paths (P04-S025, P04-S032, P04-S039, P04-S043; P04-S069 to P04-S076).
8. In `resample`, "partial" covers only the session-tail overrun: a still-forming or incomplete bucket is not flagged, for a call during the session every later slot is reported empty, a daily bar carries the session-open time, and the function is not told the base timeframe (P04-S046, P04-S054, P04-S055).
9. `resample` places each base candle by its `ts`, so the result depends on whether candles are stamped at their start or their close; the tests use start-stamped candles, while the live `CandleData` field comment says close time; `resample` has no non-test caller (P04-S015, P04-S057, P04-S058, P04-S082; Rama's decision B).
10. `resample` and `intraday_anchors` use each candle's wall-clock time without zone conversion, and `resample` raises on mixed naive and aware candles (P04-S056, P04-S074).
11. `watchlist.entry_tf` and its two "built via candle_math.resample" comments, while the entry stage uses a literal and `resample` would reject `"5minute"` (A02 K-26, kept; P04-S079, P04-S080, P04-S095).
12. The regime engine passes the whole fetched intraday window to `adx`, without a date or session filter; with `intraday_lookback_days` 1 that window is the last 24 hours (P04-S071, call 9 of P04-S068). The meaning for the day-type axis is A18's.
13. Through the fetcher cache, candles passed to the module can be up to 30 minutes old by default, and the cache key ignores the lookback (P04-S077; the cache is A08's).
14. The schemas do not check that every period passed is positive (`ema_fast`, `ema_slow`, `adx_period`, `atr_period`, `htf_ema_period`); a bad value raises `ValueError` inside the module and is caught by the callers' wrappers (P04-S072, P04-S075).
15. The live screener's ATR and RSI inputs are `None`, no screening module imports the module, and the `daily_symbol_stats` helpers have no non-test caller, while legacy documents describe the M-S4 "substrate" as shipped (P04-S070, P04-S088; A07's, A03's, A15's and A18's).
16. Two VWAP computations are in use: the broker quote's `average_price` in live screening and the typical-price VWAP from 5-minute bars of the S&R anchors (P04-S091).
17. Values are returned unrounded and never snapped to a tick; there is no NaN or infinity check (P04-S061; CG-27: P04-S062).
18. The legacy documents' test counts (26, 31) and "unwired" statements describe an earlier state (P04-S084).
