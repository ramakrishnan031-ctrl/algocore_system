## 3. Construction and indexes (`__init__`); duplicate symbols and tokens

P05-S016. FACT (L86 to L94): `InstrumentCache.__init__(self, rows: List[InstrumentRow])` stores `list(rows)` as `_rows` (L92) and builds two dictionaries, `_by_symbol = {r.symbol: r for r in rows}` (L93) and `_by_token = {r.instrument_token: r for r in rows}` (L94). It validates nothing, logs nothing and raises nothing of its own. HISTORICAL (docstring L87 to L91): "Called by load(); not typically called directly." FACT (AST, P05-S001): `__init__` is the only method of the class that assigns an instance attribute.

P05-S017. INTERPRETATION (dictionary-comprehension semantics, confirmed in P05-S007): when two rows share a key, the later row wins. With two rows of one `symbol`, `has`, `get_by_symbol`, `sector`, `lot_size` and `tick_size` see only the later row; with two rows of one `instrument_token`, `get_by_token` returns only the later row. `_rows` keeps every row, so `all_rows()` and `count()` include the duplicates (L255, L297). `token_map()` is built from `_rows` (L293): each token maps to the symbol of its last row, and two rows of one symbol with different tokens put both tokens in the map, each pointing to that symbol, while `get_by_symbol` returns only the later row's token. Neither `__init__` nor `load` reports, counts or refuses duplicates.

P05-S018. INTERPRETATION (duck typing; P05-S007 item 20): `__init__` accepts any iterable whose elements have `symbol` and `instrument_token` attributes; for other elements the comprehension at L93 raises `AttributeError`; a string passed as `rows` is iterated character by character and so raises `AttributeError` at L93. The only non-test direct construction is `scripts/sr_level_export.py` L141, which passes a path string (section 8, P05-S086; A01 C38b).

## 4. `load(path)` step by step, and the exception for each file problem

P05-S019. FACT (L98 to L110): `load` is a `@classmethod` taking `path: Path` and returning a new `InstrumentCache`. HISTORICAL (docstring L106 to L109): "Raises: ConfigMissingError: file does not exist. ConfigSchemaError: a required column is absent or a row has a type-conversion error."

P05-S020. FACT (L111 to L115): the first step, outside any `try`, is `if not path.exists():`, which raises `ConfigMissingError(f"instruments.csv not found at {path}", path=str(path))`. INTERPRETATION (the local standard library's `Path.exists`, read as text: it returns False for "not found" kinds of error and re-raises any other `OSError`; the production Python version is UNKNOWN / NOT ESTABLISHED, A01 B-41): an error other than "not found" raised by `exists()` itself, for example a permission error on a parent directory, leaves `load` as that `OSError` subclass, unwrapped, because L111 precedes the `try` that begins at L124.

P05-S021. FACT (L117 to L126): the required columns are the set `symbol`, `instrument_token`, `exchange`, `lot_size`, `tick_size`, `is_fno`, `sector` (L117 to L120). Inside the `try` that begins at L124, the file is opened with `open(path, newline="", encoding="utf-8")` (L125) and read with `csv.DictReader(fh)` (L126) using the default dialect (comma-separated, double-quote quoting) and the default `restval` (`None`) and `restkey` (`None`).

P05-S022. FACT (L127 to L138): if `reader.fieldnames is None`, `load` raises `ConfigSchemaError("instruments.csv is empty or has no header row", path=...)` (L127 to L131); otherwise it computes `missing = required_columns - set(reader.fieldnames)` and, if any column is missing, raises `ConfigSchemaError(f"instruments.csv missing required columns: {sorted(missing)}", path=..., missing_columns=sorted(missing))` (L132 to L138). Column order and extra columns are not checked.

P05-S023. INTERPRETATION (`csv` semantics, P05-S007 items 1, 2, 5, 8 and 12): `fieldnames` is `None` only when the file yields no line at all (a 0-byte file); a file whose first line is blank gets an empty header list and so the "missing required columns" error naming all seven; extra columns are read and ignored; when a column name is repeated, the last value is kept; header names are compared exactly, so a different case or a space around a name counts as missing; and a UTF-8 byte-order mark becomes part of the first header name (the encoding is `"utf-8"`, not `"utf-8-sig"`), so a file that begins with a mark and `symbol` reports `symbol` as missing.

P05-S024. FACT (L140 to L150): each data row is numbered by `enumerate(reader, start=2)` (L140) and built, in this order, as `symbol=raw["symbol"].strip()`, `instrument_token=int(raw["instrument_token"])`, `exchange=raw["exchange"].strip()`, `lot_size=int(raw["lot_size"])`, `tick_size=float(raw["tick_size"])`, `is_fno=raw["is_fno"].strip().lower() in ("true", "1", "yes")`, `sector=raw["sector"].strip()`. Only `symbol`, `exchange`, `is_fno` and `sector` are stripped; no value is upper-cased or otherwise normalised.

P05-S025. INTERPRETATION (conversion semantics, P05-S007 items 9 and 19): `int()` accepts surrounding white space, a leading sign and underscores between digits, and rejects a decimal point (for example `12.0`) and an empty cell; `float()` also accepts `nan`, `inf` and exponent forms; `is_fno` is True only for `true`, `1` or `yes` (any case, after stripping), and every other value, including `t`, `y`, an empty cell or a misspelling, becomes False without any error.

P05-S026. FACT (L151 to L156): a `KeyError` or `ValueError` raised while the row is built becomes `ConfigSchemaError(f"instruments.csv line {lineno}: {exc}", path=..., line=lineno)`, chained from the original exception. INTERPRETATION (`csv` semantics): after the header check has passed, `raw[...]` cannot raise `KeyError` for a required column, because `DictReader` gives every header name a key in every row; the arm that does the work is `ValueError`, for text that does not convert.

P05-S027. INTERPRETATION (`csv` and Python semantics, P05-S007 items 4, 7 and 9): a data row with fewer fields than the header gets `None` for the missing trailing columns (`restval`); `int(None)` and `float(None)` raise `TypeError` and `None.strip()` raises `AttributeError`; neither is caught at L151 (`KeyError`, `ValueError`) or at L180 (`OSError`, `UnicodeDecodeError`), so such a row ends `load` with an unwrapped `TypeError` or `AttributeError`, not with the `ConfigSchemaError` that IC12 and the docstring describe. With the writer's column order (section 9) and the keyword arguments evaluated in source order, a row with 1, 3 or 4 fields gives `TypeError` (L144, L146 or L147) and a row with 2, 5 or 6 fields gives `AttributeError` (L145, L148 or L149). A line holding only spaces is such a short row (one field). A row with more fields than the header is accepted: the extra values go to the key `None` (`restkey`) and are ignored.

P05-S028. FACT (L158 to L178): after a row is built, three checks raise `ConfigSchemaError` with the line number: an empty `symbol` after stripping (L158 to L163), `lot_size < 1` (L164 to L170), and `tick_size <= 0` (L171 to L177); the row is then appended (L178). Nothing else is checked: not the token's value (0 and negative tokens are accepted), not `exchange` (any text, the empty text included), not `sector`, not the characters or case of `symbol`, not repeated symbols or tokens, and not the number of rows.

P05-S029. INTERPRETATION (floating-point comparison semantics, P05-S007 item 10): `tick_size <= 0` is False for `nan` and for `inf`, so a row whose tick is `nan` or `inf` passes L171 and is loaded; `-0` is refused. Whether the writer can produce such a value is part P07's; whether the deployed file held one is UNKNOWN / NOT ESTABLISHED.

P05-S030. FACT (L180 to L184; `core/exceptions.py` L30, L56, L64, L69): an `OSError` or `UnicodeDecodeError` raised inside the `try` (L124 to L178) becomes `ConfigMissingError(f"Could not read instruments.csv at {path}: {exc}", path=...)`, chained. `ConfigSchemaError` and `ConfigMissingError` both derive from `ConfigError`, which derives from `TradingSystemError(Exception)`; neither is an `OSError`, so the `ConfigSchemaError`s raised inside the `try` pass L180 unchanged. INTERPRETATION (Python semantics; P05-S007 items 11, 13 and 15): the file is read at `reader.fieldnames` (L127) and at each step of the loop (L140), both outside the inner `try` (L141 to L156), so bytes that are not UTF-8 are always reported as `ConfigMissingError` ("Could not read"), never as `ConfigSchemaError`, although `UnicodeDecodeError` is a kind of `ValueError`. A path that is a directory (`IsADirectoryError`) or a file without read permission (`PermissionError`) also gives `ConfigMissingError`. HISTORICAL (`core/exceptions.py` L65, L70): the two classes' docstrings describe "a config file loaded successfully but failed Pydantic schema validation" and "a required config file or required config key is absent"; here `ConfigMissingError` also covers a present file that cannot be read or decoded.

P05-S031. INTERPRETATION (`csv` semantics, P05-S007 item 14): a `csv.Error` raised by the reader, for example for a field longer than the module's field-size limit (131072 characters by default), is neither an `OSError` nor a `ValueError` and leaves `load` unwrapped.

P05-S032. FACT (L186): `load` returns `cls(rows)`. There is no minimum row count: a file with a valid header and no data rows returns an empty cache (`count()` is 0) with no error. The first problem found ends the load; no row is skipped and no partial cache is returned.

P05-S033. INTERPRETATION (`csv` semantics, P05-S007 item 6): the line number in the messages counts data records from 2, not physical lines: blank lines (which `DictReader` skips) and quoted fields that span lines make it smaller than the physical line number of the faulty row.
