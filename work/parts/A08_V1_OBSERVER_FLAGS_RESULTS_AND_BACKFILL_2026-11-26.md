### 4.2 Lifecycle and threading

- P03-S030 FACT (`start`, L110 to L116): returns at once if `not self._enabled` or a worker is already set; otherwise clears the stop event, creates `threading.Thread(target=self._run, name="sr-detector", daemon=True)`, starts it and logs at INFO "sr_detector: worker started (mode=%s, version=%s)" with `_mode` and `_version`.
- P03-S031 FACT (`stop(timeout: float = 2.0)`, L118 to L127): sets the stop event; tries `self._q.put_nowait(_SENTINEL)` and ignores `queue.Full`; if a worker is set, `join(timeout=timeout)`; then sets `self._worker = None` in every case. It logs nothing and does not drain or count the queue.
- P03-S032 FACT (the worker loop `_run`, L144 to L158): `while not self._stop.is_set()`: `item = self._q.get(timeout=0.25)`, `continue` on `queue.Empty`; then, inside `try`: skip the sentinel (L151 to L152) or call `self.process_candidate(item)` (L153); `except Exception as exc` logs at ERROR "sr_detector: worker error for %s: %s" with `getattr(item, "symbol", "?")` (L154 to L156); `finally: self._q.task_done()` (L157 to L158).
- P03-S033 INTERPRETATION (what `stop` leaves; from P03-S031, P03-S032 and P03-S005 (a), (b)): (a) a candidate being processed when `stop` is called is finished (fetches, analysis and write), because the loop tests the stop event only between items; (b) candidates still in the queue are not processed: after the current item the loop condition fails, and when the worker was idle in `get` the next item it takes is normally the sentinel; they are dropped without a log line or a row; (c) `join` waits at most 2.0 s; a worker still inside a candidate's fetches is left running, unreported, and `_worker` is set to `None` anyway; as a daemon thread it is stopped abruptly when the interpreter exits ("Their resources (such as open files, database transactions, etc.) may not be released properly"); (d) a `start()` after a timed-out `stop()` would pass the `_worker is not None` test and start a second worker beside the first; at the baseline no caller does this (`main.py` starts once, L3504, and stops once, L1697).
- P03-S034 FACT and INTERPRETATION (threads and locks): the file creates one thread, "sr-detector" (L114), and holds no lock of its own (`git grep -n -i lock` on the file: no lock object); its synchronisation is the queue's internal locking (P03-S005 (a)) and the fetcher's own lock (`sr_detector/fetch.py` L51; see part P02). When fed by `observe`, `process_candidate`, `analyze` and `_write` run only on the worker thread, one candidate at a time ("A single serialized background worker", L7). `process_candidate` is public and synchronous "so tests can drive it deterministically" (L160 to L163); `analyze` is also called directly by the export script on its own thread (P03-S023; part P05). INTERPRETATION: the fetches of the V1 worker can run at the same time as fetches of the other A08 and A18 threads through the shared closure (P07-S020, A01 C38a; P07-S130, A04 RL-11; part P02).
- P03-S035 FACT (the wiring in `main.py`, A01's file, interface only): `_sr_cfg = app_config.system.sr_detector` and `_v1_on = _sr_cfg.enabled` (L3421 to L3422); the shared fetch closure `_sr_fetch_fn = _make_sr_fetch_fn(_md_kite, rate_limiter)` is built when any of six switches is on (L3479 to L3487); under `if _v1_on:` (L3491), inside `try` (L3492), `build_sr_detector(config=_sr_cfg, fetch_fn=_sr_fetch_fn, instrument_cache=instrument_cache, store=store, logger=get_logger("sr_detector"), mode=mode_label, session_open=market_windows.market_open, session_close=market_windows.market_close)` (L3494 to L3503) with no `now_fn` (so `now_ist`, P03-S018), then `sr_detector.start()` (L3504) and INFO "sr_detector: ENABLED and started (mode=%s)" (L3505); `mode_label` is `str(args.mode or "live").upper()` (L2645, set again after L2241). The detector is passed to `SignalProcessor(..., sr_detector=sr_detector, ...)` (L3607) and to `_shutdown(..., sr_detector=sr_detector, ...)` (L4266), which calls `sr_detector.stop()` after `signal_proc.stop()`, in `try`, logging "sr_detector.stop error: %s" (L1690 to L1699; comment L1693 to L1694 "after signal_processor so no new candidates are enqueued. Daemon thread; best-effort"). `store` is the process's `StateStore`, the one the order path uses.
- P03-S036 INTERPRETATION (what the worker does before any placement; A01 C13's A08 side; from P03-S032, P03-S035): the worker is started at L3504, before the `SignalProcessor` is built (L3575) and before the later startup steps of `main.py`; until `observe` puts a candidate on the queue it only waits in `get` with a 0.25 s timeout, so it makes no fetch, no write and no log line. Its first fetch follows the first placement that reaches `_sr_observe` (section 7).

### 4.3 `observe`

- P03-S037 FACT (`observe`, L131 to L140; docstring "Enqueue a placed candidate and return immediately. Never raises."): `if not self._enabled: return`; then `try: self._q.put_nowait(candidate)`; `except queue.Full:` WARNING "sr_detector: queue full, dropping %s" with `candidate.symbol` (L137 to L138); `except Exception as exc:` ERROR "sr_detector: observe() failed: %s" (L139 to L140, comment "belt-and-suspenders; the pipeline must not see this"). Both log calls go through `_safe_log` (L311 to L317), which returns if the logger is `None` and swallows any exception of the logging call.
- P03-S038 INTERPRETATION (non-blocking; P03-S005 (a)): `put_nowait` either places the candidate at once or raises `Full`; it never waits for a free slot, and it does not wait for the analysis. A full queue (256 candidates waiting at the loader default) drops the new candidate: no row is ever written for it, and the WARNING line is the only record.
- P03-S039 INTERPRETATION (what runs on the caller's thread): the `_enabled` test, one `put_nowait` (which takes the queue's internal lock briefly, P03-S005 (a): "implements all the required locking semantics") and, only on a full queue or an unexpected exception, one log call with the logger's handler work. Nothing else of the observer runs on the caller's thread.
- P03-S040 INTERPRETATION (the one unguarded expression): in the `queue.Full` handler the argument `candidate.symbol` (L138) is evaluated before `_safe_log` is entered, outside any further `try`; an object without a `symbol` attribute would raise `AttributeError` out of `observe`. Every production caller passes a `Candidate` built by `_sr_observe` (`signals/signal_processor.py` L641 to L654; P01-S032), whose `symbol` field always exists, so the case does not arise on the baseline's paths.
- P03-S041 FACT and INTERPRETATION (behaviour when disabled): with `_enabled` false, `start` creates no thread (L111) and `observe` returns at once (L133 to L134); `process_candidate` and `analyze` still work when called directly (they do not test the flag). INTERPRETATION: `main.py` builds the detector only when `enabled` is true (L3491), so in the trading process `_enabled` is always true when a detector exists and the off state is "no detector" (`sr_detector=None`; `_sr_observe` returns at `signals/signal_processor.py` L637 to L638); the export script forces `enabled: True` in its copy (`scripts/sr_level_export.py` L152 to L155) and never calls `start` or `observe`. The flag-false detector arises only in tests (`tests/unit/test_sr_detector_observer.py` L136 to L144).

### 4.4 The per-candidate computation (`process_candidate`, `analyze` and helpers)

- P03-S042 FACT (`process_candidate`, L161 to L163): `analysis = self.analyze(candidate)`, then `self._write(candidate, analysis)`. No `try` here: an exception from `analyze` skips `_write` (P03-S055).
- P03-S043 FACT (step 1, the fetch, L168): `tf_candles = self._fetcher.fetch_timeframes(candidate.symbol, self._intervals)`. Contract (see part P02; `sr_detector/fetch.py` `fetch_timeframes` L53 to L68, docstring L54 to L58): a dict `{interval: [Candle, ...]}` holding only the intervals that fetched non-empty; a failed or empty interval "is simply omitted (never raises)"; an empty dict when the symbol's token cannot be resolved or every interval failed. Each interval's window runs from the fetcher's clock time minus `lookback_days` to the fetcher's clock time at the call (`sr_detector/fetch.py` L122 to L125; see part P02), with committed `lookback_days: 180` (P03-S019).
- P03-S044 FACT (empty fetch, L169 to L174): `return SRAnalysis(structure_status=STRUCT_FETCH_FAILED, flags=("NO_CLEAR_STRUCTURE",), note="fetch_failed")`; every other field keeps its default (no zones, `None` distances and breakout volume, `RetestProposal()` with `would_wait=False`, empty evidence, anchors and swings, `confidence_class="ANCHOR_ONLY"`; P01-S037). `STRUCT_FETCH_FAILED` is `"FETCH_FAILED"` (`sr_detector/models.py` L167). The `note` field is not written to the row (P03-S090).
- P03-S045 FACT (step 2, zones, L176 to L177): `scored = scored_zones_from_candles(tf_candles, knobs=self._knobs, scoring=self._scoring, now=self._safe_now())` (`sr_detector/zone_builder.py` L85 to L107; see part P02; the calculations are P01's, P01-S102). `_safe_now` (L305 to L309) returns `self._now_fn()` or `None` if the call raises (P01-S091: a `None` clock gives every dated zone the full recency vote).
- P03-S046 FACT (steps 3 and 4, L178 to L179): `breakout = self._breakout_context(tf_candles)`; `fr = compute_flags_and_retest(candidate, scored, breakout, self._flagp)` (section 5).
- P03-S047 FACT (step 5, status and flags, L181 to L182): `status = STRUCT_OK if scored else STRUCT_NONE` (`"OK"` or `"NO_CLEAR_STRUCTURE"`, `sr_detector/models.py` L165 to L166); `flags = fr.flags if fr.flags else (("NO_CLEAR_STRUCTURE",) if status == STRUCT_NONE else ())`.
- P03-S048 INTERPRETATION (the fallback at L182; from P03-S047 and `sr_detector/flags.py` L74 to L76): when `scored` is empty, `compute_flags_and_retest` already returns `("NO_CLEAR_STRUCTURE",)`, so `fr.flags` is non-empty and the fallback branch is never taken; when `scored` is not empty, an empty flag tuple stays empty. `STRUCT_OK` means at least one scored zone of any confidence, LOW included (P01-S070: no zone is filtered out).
- P03-S049 FACT (step 6, anchors and swings, L184 to L192): `anchors` and `swings` start as empty dicts; only `if self._anchors_on:` are they filled by `self._build_anchors(candidate, tf_candles)` and `build_swings_payload(scored)` (`sr_detector/zone_builder.py` L207 to L224; see part P02). The comment L184 to L187: "confidence_class stays ANCHOR_ONLY — swings are computed + emitted but NOT-YET-VALIDATED, so they never drive the later R:R gate until Rama's validation flips it." Committed `intraday_anchors_enabled: false` (L542).
- P03-S050 FACT (the `SRAnalysis` built, L194 to L207): `structure_status=status`; `nearest_resistance`, `nearest_support`, `dist_to_resistance_pct`, `dist_to_support_pct` and `retest` from `fr`; `breakout_volume=(breakout.last_volume if breakout else None)`; `flags=flags`; `evidence=self._evidence(scored)`; `anchors`, `swings`; `confidence_class=CONF_ANCHOR_ONLY` (always; P01-S035). - P03-S051 FACT (`_build_anchors`, L209 to L235; docstring "Fail-safe — a fine-fetch miss yields None fields, never raises"): `daily = tf_candles.get("day") or []`; `reference = float(candidate.intended_entry) if candidate.intended_entry else None`; `intraday = None`; only when both session bounds are set (L217) and `candidate.ts` is not `None` (L218 to L219): inside `try`, `fine = self._fetcher.fetch_interval(candidate.symbol, self._anchor_interval, self._anchor_lookback_days) or []` (L221 to L223) and `intraday = intraday_anchors(fine, on_date=candidate.ts.date(), session_open=..., session_close=..., orb_window_minutes=...)` (L224 to L230); `except Exception` logs WARNING "sr_detector: intraday anchors failed for %s: %s" and sets `intraday = None` (L231 to L234). It returns `build_anchor_payload(daily, reference, intraday)` (L235), which is outside the `try`. `fetch_interval`, `intraday_anchors` and `build_anchor_payload` are part P02's (`sr_detector/fetch.py` L70 to L83; `sr_detector/zone_builder.py` L143 to L182, L185 to L204). With committed values the fine fetch asks for `5minute` bars over 1 day.
- P03-S052 FACT (`_breakout_context`, L237 to L250): `intr = tf_candles.get("30minute") or tf_candles.get("60minute") or tf_candles.get("day")`; `None` if none is present; `last = intr[-1]`; `window = intr[-(self._breakout_avg_window + 1):-1]`; `avg_vol = mean([c.volume for c in window]) if window else float(last.volume)`; returns `BreakoutContext(last_close=last.close, last_high=last.high, last_low=last.low, last_volume=float(last.volume), avg_volume=float(avg_vol))`.
- P03-S053 INTERPRETATION (what the "breakout candle" is; from P03-S052, P03-S043, P01-S094): with the committed timeframes the breakout candle is the last element of the 30-minute list (the 60-minute list if the 30-minute interval failed, the daily list if both failed); "last" is list position, which is the newest candle only if the fetched rows are in ascending time (nothing sorts them, P01-S021; A05 CM-05); the average is the arithmetic mean of the volumes of up to 20 candles before it (fewer when the list is shorter; the last candle's own volume when it is alone). The breakout candle is not tied to the candidate: it is the last candle the fetch returned at processing time, whether or not it contains the placement time, and it can be a candle still forming (P03-S057; A05 HA-04). Volumes are `Candle.volume` integers, 0 where the broker gave none (P01-S018).
- P03-S054 FACT (`_evidence`, L252 to L255): `{"resistance_zones": [...], "support_zones": [...]}`, each the `to_dict()` (P01-S028) of the first `max_zones_logged` (loader 12) zones of that kind in the order of `scored`, which is ascending centre (P01-S093); P01-AP12 records that with more than twelve zones of a kind the lowest-priced are kept.
- P03-S055 INTERPRETATION (exceptions inside the computation; from L161 to L207, which contain no `try` apart from the fine fetch's, and P03-S032): an exception raised by `fetch_timeframes` (whose docstring says it never raises; whether it can is part P02's, `sr_detector/fetch.py` L114 to L147), by `scored_zones_from_candles` (for example the `ValueError`, `OverflowError` or `TypeError` cases of P01-S097), by `_breakout_context`, `compute_flags_and_retest`, `build_swings_payload`, `build_anchor_payload` or `_evidence` leaves `analyze`, skips `_write` and reaches `_run`'s handler: one ERROR line "sr_detector: worker error for <symbol>: <exception>", no row, no counter increment. A fetch failure that the fetcher absorbs gives instead a `FETCH_FAILED` row (P03-S044). So a placed candidate can end with a row, with a `FETCH_FAILED` row, or with no row and an ERROR line.
- P03-S056 INTERPRETATION (a partial fetch; from P03-S043, P03-S047): when one or two of the three intervals fail, the analysis runs on the others and the row's `structure_status` is `OK` if any zone results; nothing in the row records which intervals were fetched and which failed (the zones' `timeframes` show only those that contributed). With one interval left, no zone can be HIGH (two timeframes are needed, P01-S080), so no `BUYING_INTO_RESISTANCE` or `SELLING_INTO_SUPPORT` flag and no proposal can arise.
- P03-S057 INTERPRETATION (as of when the analysis is made; A05 HA-04's A08 side; from P03-S043, P03-S032, P03-S038): the window of every fetch ends at the clock time when the worker processes the candidate, not at `candidate.ts` (the placement-time stamp), and nothing in `analyze` truncates candles to `candidate.ts` or drops a still-forming last candle (search of the A08 paths for `forming`, `partial`, `incomplete`, `as_of`, `truncat`, `lookahead`: no hit in `sr_detector/`; P03-S203). The worker takes candidates in arrival order, each needing up to three fetches (four with the anchors), each paced by the shared limiter's "historical" category (`main.py` L431, A04's limiter), and fetches inside the cache time (committed 1800 s, P03-S019) return the cached lists; so the candles analysed can end before or after the placement by amounts the code does not bound, and can include price action after the entry. The row stores both `ts` (the placement-time stamp) and `created_at` (the write time) (P03-S085), from which the delay of each row can be read.
- P03-S058 FACT (what the detector does not call; reading of the file and P03-S011): `detector.py` calls only the fetcher (`fetch_timeframes` L168, `fetch_interval` L221), the seven `zone_builder` functions, `compute_flags_and_retest`, the store's `insert_sr_detector_result` (L295, its only use of the store), the telemetry counter's `inc()` (L298), the clock (L307) and the logger (L315). It calls no order, signal, trade, capital, risk, kill-switch, alert or event-bus method and writes no other table.
