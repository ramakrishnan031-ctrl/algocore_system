## 1. Shared mechanics this range relies on (pointers; see part P01)

| ID | Statement |
|---|---|
| P05-S006 | FACT. Every write method in this range uses `with self.transaction() as cur:`. `transaction()` (`core/state_store.py` L505 to L543) issues `BEGIN IMMEDIATE`, yields a cursor, issues `COMMIT` on normal exit, and on any exception issues `ROLLBACK` (ignoring a `sqlite3.Error` from the ROLLBACK itself) and re-raises. Nested use is documented as unsupported (L517 to L519). See part P01. |
| P05-S007 | FACT. `fetch_one` and `fetch_all` (L564 to L586) execute on the thread's connection without `transaction()`; the connection is opened with `isolation_level=None` (L232 to L237), so these reads run in autocommit mode (INTERPRETATION: each SELECT is its own implicit read transaction). Errors propagate to the caller. |
| P05-S008 | FACT. Every connection ATTACHes `analytics.db` as schema `analytics` (L247; `core/db_connect.py` L52 to L64). `candles` exists only in `analytics.db` (`core/analytics_schema.sql` L24 to L39), so the unqualified `candles` in `insert_candle`, `compute_trade_excursions` and `get_candles_for_date` resolves to `analytics.candles` (`core/db_connect.py` L10 to L14, HISTORICAL description; INTERPRETATION of SQLite name resolution).
