## 3. `OhlcFetcher`: windows, cache, conversion, ordering, errors

### 3.1 The constructor and the injected fetch function

### 3.2 The three public methods

- P02-S015 FACT (`fetch_timeframes`, L53 to L68): it resolves the token (L59); `None` gives `{}` (L60 to L61). Otherwise, for each interval in the order given, it calls `_fetch_one(symbol, token, interval)` with no lookback, so the constructor's lookback applies (L64 to L65, L123), and adds `out[interval] = candles` only when the result is truthy (L66 to L67). The intervals are fetched one after another on the caller's thread. It has no lookback parameter. Docstring L54 to L58: "Return {interval: [Candle,...]} for the intervals that fetched OK. A failed/empty interval is simply omitted (never raises). An empty dict means the detector should record a fetch_failed / NO_CLEAR_STRUCTURE row."
- P02-S016 INTERPRETATION (what the result tells a caller; from L59 to L68): a failed interval and an empty one are both simply absent, with no marker, so a caller cannot tell from the result which intervals were attempted, which failed and which were empty (failures are visible only as WARNING lines, P02-S037); a token failure and the failure of every interval both give `{}`. The result keeps the order of the requested intervals. An interval listed twice is fetched once and served from the cache the second time within the TTL (fetched twice with a TTL of 0) and appears once (the loader's validator checks only that `timeframes` is non-empty and holds allowed values, `core/config_loader.py` L1243 to L1255, A02's).
- P02-S017 FACT (`fetch_interval`, L70 to L83): it resolves the token; `None` gives `None` (L80 to L82); otherwise it returns `_fetch_one(symbol, token, interval, lookback_days=lookback_days)` (L83). V3 03.01: the Layer-A intraday anchors (VWAP/ORB) need TODAY's fine bars (e.g. 5-minute, lookback 1) — a different window than the multi-day structural fetch. Reuses the same token/cache/fetch_fn machinery; returns None on any failure (fail-safe, SR-F4). fetch_timeframes() is unchanged."
- P02-S018 FACT (`fetch_by_token`, L85 to L101): `if not token: return None` (L98 to L99), with no log line; then `key = cache_key or f"__token_{int(token)}"` (L100) and `return self._fetch_one(key, int(token), interval, lookback_days=lookback_days)` (L101). - P02-S019 INTERPRETATION (`fetch_by_token`'s edge cases; from L98 to L101 and P01-S005): `int(token)` at L100 (when no `cache_key` is given) and at L101 runs outside any `try`, so a truthy token that `int` cannot convert raises `ValueError` or `TypeError` to the caller, against the docstring's "Returns None on any failure"; a fractional float token is truncated; a negative token is used as given. ### 3.3 Token resolution

- P02-S020 FACT (`_resolve_token`, L105 to L112): inside a `try`: `row = self._cache.get_by_symbol(symbol)` (L107), `token = int(getattr(row, "instrument_token"))` (L108), `return token or None` (L109); any exception (comment L110: "InstrumentNotFoundError or anything") is logged as WARNING "sr_detector fetch: token lookup failed for %s: %s" with the symbol and the exception, and `None` is returned (L110 to L112). A token of 0 therefore gives `None` without any log line: the WARNING is written only when an exception occurs (A05 IN-02 records the same at its boundary).
- P02-S021 INTERPRETATION (the cases; from L105 to L112, P02-S005 (e)): a symbol missing from the instrument cache (the cache's exception, A05's), a row without the attribute (`AttributeError`) and a row whose token is `None` (`TypeError`) are logged and give no candles; a row with token 0 gives no candles silently; a negative token is passed on as a token; the symbol string is used exactly as given (no case or whitespace normalisation). The instrument cache is called with no lock of the fetcher; its own thread safety and its handling of placeholder rows are A05's (IN-02, IN-09).

### 3.4 The request window

- P02-S022 FACT (`_fetch_one`, L114 to L136, in order): `cached = self._cache_get(symbol, interval)` (L118) runs first and outside the `try`; a non-`None` result is returned at once (L119 to L120). Inside the `try` (L121 to L129): `now = self._now_fn()` (L122); `lb = self._lookback_days if lookback_days is None else int(lookback_days)` (L123); `from_dt = now - timedelta(days=lb)` (L124); `rows = self._fetch_fn(token, from_dt, now, interval)` (L125); `candles = [Candle.from_kite(r) for r in (rows or [])]` (L126); `if candles: self._cache_put(symbol, interval, candles)` (L127 to L128); `return candles or None` (L129). `except Exception as exc` logs the WARNING of P02-S037 and returns `None` (L130 to L136).
- P02-S023 FACT and INTERPRETATION (the window; from L122 to L125): FACT: the window is from `now − lb` days to `now`, where `now` is the injected clock read at the moment of the miss and `lb` the call's lookback or, if none, the constructor's; `timedelta(days=lb)` counts calendar days. FACT: no market hours, session open or close, trading calendar, weekend, holiday or "today" is applied, and neither end is rounded to a bar or day boundary. INTERPRETATION: `to` is the current moment, so the window includes the current session up to the call; `from` falls at the same wall-clock time `lb` calendar days earlier, so a 180-day window covers about 180 calendar days of whatever sessions the broker returns; an explicit `lookback_days=0` gives `from == to`, and a negative value puts `from` after `to`; neither is rejected. FACT (time zone): every non-test construction in the trading process passes `time_authority.now_ist` (section 3.8), which returns `datetime.now(tz=_IST)` with `_IST = timezone(timedelta(hours=5, minutes=30), name="IST")` (`core/time_authority.py` L58 to L59, L94 to L99; interface), so the closure receives two aware IST datetimes; the export script's per-call detector passes a constant naive time instead (P01-S137; P05's). How the library turns the datetimes into the request's `from` and `to` is A05's; the vendor page states no time zone for them (P02-S004).
- P02-S024 INTERPRETATION and UNKNOWN / NOT ESTABLISHED (a still-forming last candle; from L122 to L129): the fetcher applies no as-of truncation and no completeness test: whatever the answer to a window ending "now" contains is converted, cached and returned as received, including, if the broker sent one, a still-forming last intraday candle or today's daily candle during the session. Whether the legacy server's answers contained such a candle is UNKNOWN / NOT ESTABLISHED (A05 HA-04; P01-S096); the vendor page's example says only that the latest record reflects the time of the request (P02-S004). The consequences for the zones are P01-S096's; for the prior-day levels and the anchors, P02-S048 and P02-S058.

### 3.5 Row conversion, ordering and empty results

- P02-S025 FACT (conversion; P01-S015 to P01-S019): the rows are converted with `Candle.from_kite` in the order the closure returned them (L126); the comprehension is inside the `try`, so one row that `from_kite` cannot convert (a missing key, a `None` or non-numeric price, a non-integral volume string) makes the whole interval `None` with one WARNING, and no row is skipped individually (P01-S019); NaN and infinite prices pass through (P01-S017). `rows or []` turns `None`, an empty list or any other falsy answer into an empty list. INTERPRETATION: a truthy answer that is not a list of dictionaries (for example a dictionary, which iterates over its keys) fails in `from_kite` and is logged as "historical_data failed".
- P02-S026 FACT and INTERPRETATION (ordering, duplicates, gaps, validation: A05 CM-05's A08 side): FACT: no line of the four files sorts candles, removes duplicates, detects gaps, checks that timestamps increase, compares a candle's date with the request, or checks the values; `fetch.py` converts and caches the list in the closure's order (L126 to L128) and returns the same list on a cache hit (L147); `zone_builder.py` passes each series to the calculation core unchanged (L94 to L97, L99 to L103), takes `daily[-2]` as the prior day by position (L81) and filters the anchors' bars by date and time (L160 to L163, L172). INTERPRETATION: the zones and the volume profile do not depend on order except through the pivots (P01-S045, P01-S094); `prior_day_levels` assumes an ascending series (P02-S048); the anchors' filters and `max`/`min` do not depend on order; a duplicated candle is counted twice by the pivots, the volume profile and the VWAP (P01-S095; `session_vwap` sums every bar given, `core/candle_math.py` L149 to L155, A05's). Whether the legacy server's rows were always ascending and unique is UNKNOWN / NOT ESTABLISHED (A05 CM-05; P01-U02). The fetch test's fixture rows are newest first (P01-S126).
- P02-S027 FACT and INTERPRETATION (empty results; from L126 to L129 and `main.py` L429 to L430): FACT: an empty or `None` answer gives an empty list, which is not cached (L127) and is returned as `None` (L129), with no log line, because the WARNING is written only in the `except` branch; the closure returns `[]` when the market-data handle is `None`, so a missing handle gives the same silent `None` (A05 HA-09 records the related call-site text). INTERPRETATION: within the fetcher an empty answer, a missing handle and an answer whose every row was dropped (impossible here: no row is dropped) are indistinguishable and leave no trace; there is no negative cache, so every later call for the same key asks the closure again.

### 3.6 The cache: key, value, clock, TTL, eviction, sharing, locking

- P02-S028 FACT (key and value; L138 to L151): `_cache_put` stores `self._mem[(symbol, interval)] = (self._now_fn(), candles)` while holding the lock (L149 to L151). `_cache_get` reads `entry = self._mem.get((symbol, interval))` while holding the lock (L139 to L140), returns `None` when there is no entry (L141 to L142), then, outside the lock, computes `age = (self._now_fn() - fetched_at).total_seconds()` (L143 to L144), returns `None` when `age > self._cache_ttl_sec` (L145 to L146) and otherwise the stored list (L147). The key is the pair (first argument of `_fetch_one`, interval): the symbol for `fetch_timeframes` and `fetch_interval`, the `cache_key` or `__token_<n>` for `fetch_by_token` (L100 to L101). The key does not contain the lookback, the window's start or end, the token or the clock reading; the value is the candle list and the clock reading at the time of storing.
- P02-S029 FACT (the clock of the age): the age is the difference of two readings of the injected `now_fn`, the stored one taken at `_cache_put` (L151) and the current one at `_cache_get` (L144); in the trading process every construction passes `time_authority.now_ist` (section 3.8), a reading of the system's wall clock converted to IST (P02-S023; current external context, P02-S005 (c) and (d): `datetime.now` and `today()` derive from the system clock, `time.time()` "can return a lower value than a previous call if the system clock has been set back", and `time.monotonic()` is the clock "not affected by system clock updates"). No monotonic clock is used anywhere in the four files (P02-S009). The comment L49 calls the stored value "fetched_at_monotonic_dt" (A05 HA-06 records the same difference).
- P02-S030 INTERPRETATION (what a wall-clock age means; from P02-S028, P02-S029 and P02-S005 (c)): a backward step of the system clock makes the computed age smaller, or negative, so an entry is served for longer than the TTL; a forward step expires entries early. The age is calendar time, not market time: an entry ages at the same rate across the close, the night, weekends and holidays, and nothing ties an entry to a session (an entry stored at 15:20 is still served at 15:45 within 1800 s, whatever happened in the market meanwhile). A daily list stored early in a session keeps whatever last candle it held (P02-S024) for up to the TTL. Whether the legacy machine's clock stepped while the system ran is UNKNOWN / NOT ESTABLISHED (A05 HA-06; A17).
- P02-S031 FACT and INTERPRETATION (the TTL test and a TTL of 0; from L145): FACT: the test is `age > ttl`, so an entry whose age equals the TTL is still served. FACT: the watchlist fetcher and the one-minute fetcher are built with `cache_ttl_sec=0.0` (`main.py` L3732, L3777; section 3.8). INTERPRETATION: with a TTL of 0 an entry is served only when the computed age is 0 or negative, that is, when the read falls within the clock's resolution of the store or after a backward clock step; otherwise every call goes to the closure. Each successful fetch is still stored (L127 to L128) and kept (P02-S032). A negative TTL never serves.
- P02-S032 FACT and INTERPRETATION (no eviction, no bound; from L49 to L51, L138 to L151): FACT: no line removes an entry from `_mem`: `_cache_get` skips a stale entry but leaves it in place, and the only write is the overwrite by `_cache_put` after the next successful fetch of the same key; there is no size limit, no eviction, no clear method and no end-of-day reset. INTERPRETATION: each fetcher object keeps one candle list per distinct (key, interval) for its whole life, which for the fetchers built in `main.py` is the life of the process; the memory held grows with the number of distinct symbols fetched, and a stale list whose refetch keeps failing stays in memory, unused, until the process ends.
- P02-S033 FACT and INTERPRETATION (the same list object is shared; from L147, L151): FACT: a cache hit returns the stored list object itself, not a copy; the `Candle` objects are frozen (P01-S014), the list is not. INTERPRETATION: every caller of one fetcher object within the TTL receives the same list, so a caller that sorted, appended to or removed from it would change what later callers receive; no function in the four files changes a list it receives (`zone_builder.py` reads its series and builds new lists, `scoped` and `window`, L160 to L163, L172; no function of the calculation core modifies its arguments, P01-S010, P01-S044); the callers in other parts and topics handle the list by their own logic (the retest monitor builds a new list, `screening/retest_monitor.py` L220 to L225, P04's; the V3 and PB-01 consumers' truncation is A18's).
- P02-S034 FACT and INTERPRETATION (thread safety; from L51, L118 to L151): FACT: the one `threading.Lock` is held only for the dictionary read (L139 to L140) and the dictionary write (L150 to L151); the instrument-cache lookup, the clock reads at L122 and L144, the closure call, the conversion and the logging run without it. INTERPRETATION (P02-S005 (b)): the dictionary is safe for concurrent use by several threads; the class does not serialize fetches: two threads that miss on the same key at about the same time both call the closure and both store, the later store replacing the earlier (no single-flight and no in-flight marker), and calls on one fetcher object, or on different fetcher objects built over the one closure, can be in the closure at the same time. Which threads use which object is in section 3.8; whether calls overlapped in production, and whether the shared client tolerated it, is UNKNOWN / NOT ESTABLISHED (A01 C38a; A04 RL-11).

### 6.2 `enqueue`: the signal-arrival hook and whether it can block

- P02-S079 FACT (`enqueue`, L84 to L99): it returns at once when the warmer is not enabled or the symbol is falsy (L86 to L87). Inside a `try` (L88): under `_pending_lock`, it returns if the symbol is already pending and otherwise adds it (L89 to L92); then, after releasing the lock, `self._q.put_nowait(symbol)` (L93). On `queue.Full` it removes the symbol from `_pending` under the lock and logs WARNING "zone_warmer: queue full, dropping %s" (L94 to L97); on any other exception it logs ERROR "zone_warmer: enqueue failed: %s" (L98 to L99). Nothing is raised to the caller and nothing is returned. Docstring L85: "Queue a symbol for warming. Deduped; never raises into the caller."
- P02-S080 FACT and INTERPRETATION (can the dispatcher's zone warming block? A06 WD-10, PQ-11 and note N3; interface for A06's file): FACT: `enqueue` makes no fetch, no clock read, no store call and no cache call (L84 to L99). Its caller is A06's `_warm_zones` (`signals/signal_processor.py` L361 to L375), which takes the symbol from a dictionary's `"symbol"` or the tuple's third element (L368 to L371), calls `enqueue` only when the symbol is truthy (L372 to L373) and swallows any exception (L374 to L375); `_warm_zones` is called once per dequeued item on the single dispatcher thread "sp-dispatcher" (`_dispatcher_loop`, L377 to L390; thread L314 to L316), at L388, before `self._executor.submit(...)` (L389 to L390); the drain after a stop (L392 to L399) does not call it. INTERPRETATION (P02-S005 (a), (b)): `put_nowait` never waits for a free slot (a full queue raises `Full` at once), so the call can wait only (1) for `_pending_lock`, which the dispatcher's own calls, the worker's discard before each warm (L113 to L114) and the worker's re-warm enqueues (L124) each hold for one set operation; (2) for the queue's internal lock, which `get`, `put` and `task_done` hold briefly; and (3), on the full-queue and error paths only, for the logger call, which writes through the process's logging handlers (configured outside A08). None of the locks that `enqueue` takes is held during a fetch, a limiter wait or a broker call, so the dispatcher does not wait for the warmer's work. How long these short waits took in production was not recorded and is UNKNOWN / NOT ESTABLISHED (A06 WD-16). A06 PQ-11's MATCH row records the same reading at its boundary ("`ZoneWarmer.enqueue` holds a short lock and uses `put_nowait`", A06 AUDIT L4010).
- P02-S081 INTERPRETATION (the dedup's scope; from L89 to L92 and L113 to L115): `_pending` holds the symbols queued and not yet taken: the worker removes a symbol just before warming it (L113 to L115), so a symbol can be queued again while it is being warmed and be warmed twice in a row (the second time from the fetcher's cache inside its TTL); the match is on the exact string (case and spaces count); the dedup does not consult the zone cache, so a symbol whose `ZoneSet` is fresh is warmed again on each new signal (from the fetcher's cache inside its TTL, P02-S070); a symbol accepted while no worker runs (P02-S078, P02-S089) stays in `_pending`, and every later `enqueue` of it returns at once. The test `tests/unit/test_sr_v2_zone_cache.py` L113 to L118 states the dedup expectation for two calls with no worker running.

### 6.3 The worker, the re-warm rule and `warm`

- P02-S082 FACT (`_run`, L103 to L119): `while not self._stop.is_set()` (L104): `item = self._q.get(timeout=self._idle_sleep_sec)` (L106); on `queue.Empty`, `self._enqueue_rewarms()` (comment "idle: refresh near-expiry symbols") and `continue` (L107 to L109). Otherwise, inside a `try` (L110): the sentinel gives `continue` (L111 to L112); under `_pending_lock`, `self._pending.discard(item)` (L113 to L114); `self.warm(item)` (L115); `except Exception as exc` logs ERROR "zone_warmer: warm error for %s: %s" (L116 to L117); `finally: self._q.task_done()` (L118 to L119).
- P02-S083 INTERPRETATION (the loop; from L103 to L119 and P02-S005): one worker thread takes the symbols one at a time in arrival order; the re-warm scan runs only after the queue has been empty for `idle_sleep_sec` (2.0 s), so a steady stream of new symbols postpones it; an `Exception` raised in `warm` (for example by the fetcher's clock path, P02-S036, or by the cache's `put`, P02-S065) is logged and the loop goes on; an exception that derives from `BaseException` only would end the thread without a line of the warmer's own (P02-S005 (f)); the stop flag is read only between items and after each idle wait, so a stop takes effect after the current warm. `task_done` is called for every item taken, the sentinel included; nothing in the package calls the queue's `join` (search), so the counter has no reader.
- P02-S084 FACT and INTERPRETATION (`_enqueue_rewarms`, L121 to L126, and the re-warm rule): FACT: inside a `try`, `for sym in self._cache.symbols_due_for_rewarm(self._rewarm_margin_sec): self.enqueue(sym)` (L122 to L124); any exception is logged as ERROR "zone_warmer: rewarm scan failed: %s" (L125 to L126). INTERPRETATION (from P02-S067, P02-S068 and P02-S073): a symbol is due when its `ZoneSet` is at least `ttl − margin` old (with the committed 1800 and 300, 1500 s; values only), expired entries included, and every stored symbol stays stored; so every symbol warmed once is re-warmed about every `ttl − margin` seconds (plus the idle wait and the warm's own time) for the life of the process, after the close, at night and on holidays included: no line of the warmer or the cache tests market hours, the session or the date. In the committed-value cycle of P02-S070 alternate re-warms are served from the fetcher's cache and the others fetch afresh, three broker calls each through the shared `historical` bucket. A symbol whose re-warm fetch fails keeps its old `warmed_at` (a fetch miss leaves the entry alone, P02-S086), so it stays due and is queued again at every idle scan, about every 2 s plus the time of the failed fetch, until a fetch succeeds; each attempt goes through the limiter (no negative cache, P02-S027) and logs a WARNING in the fetcher for each failed interval (none for an empty answer) and an INFO "fetch miss" in the warmer. A margin larger than the TTL would make every stored symbol due at every scan, and a negative margin would re-warm only after expiry. The module docstring says "Re-warms cached symbols before TTL expiry" (L10).
- P02-S085 FACT (`warm`, L128 to L142): comment L128 "Public + synchronous so tests can drive it deterministically."; `tf_candles = self._fetcher.fetch_timeframes(symbol, list(self._knobs.intervals))` (L132); if it is empty, INFO "zone_warmer: fetch miss for %s (no cache update)" and `return False` (L133 to L135); otherwise `scored = scored_zones_from_candles(tf_candles, knobs=self._knobs, scoring=self._scoring, now=self._safe_now())` (L136 to L137), `resistance, support = split_zones(scored)` (L138), `self._cache.put(symbol, resistance, support)` (L139), INFO "zone_warmer: warmed %s (res=%d sup=%d)" (L140 to L141) and `return True` (L142). Docstring L130 to L131: "Fetch structure TFs, build zones, store in the cache. Returns True if zones were cached. A fetch miss leaves the cache untouched (returns False)." Its only non-test caller is `_run` (L115); the one-minute fetch the docstring excludes ("No 1-minute fetch") is indeed absent (the intervals are the knobs').
- P02-S086 INTERPRETATION (what a warm writes; from L132 to L142, P02-S015 and P02-S050): a fetch miss leaves any existing entry as it was, with its old `warmed_at`; any non-empty fetch result is stored, even when only one or two of the three intervals came back and even when no zone was found (two empty tuples; `True` is then returned although no zone was cached, against the docstring's "Returns True if zones were cached"); the `ZoneSet` records neither fact. With fewer timeframes fewer groups can be HIGH (a one-timeframe group never is, P01-S079 (c)), and without the daily series the prior-day levels and the volume nodes come from an intraday series (P02-S050 (b)). `_safe_now()` gives `None` when the clock raises (P02-S087), and a `None` `now` gives every dated zone the full recency vote (P01-S091). The two INFO lines are written for every warm, re-warms included. The scoring's `now` and the `put`'s `warmed_at` are two separate clock reads.
- P02-S087 FACT (`_safe_now` and `_safe_log`, L146 to L158): `_safe_now` returns `self._now_fn()` or, on any exception, `None` (L146 to L150); `_safe_log` does nothing when the logger is `None` and swallows any exception raised by the logger call (L152 to L158).

### 6.4 `stop`, shutdown and the switches

- P02-S088 FACT (`stop`, L71 to L80, and its call; interface for A01's file): `self._stop.set()` (L72); `self._q.put_nowait(_SENTINEL)` inside a `try` that ignores `queue.Full` (L73 to L76); if a worker exists, `w.join(timeout=timeout)` with the default 2.0 s (L77 to L79); then `self._worker = None` (L80), whether or not the join completed. It logs nothing and does not test `is_alive()`. The one non-test call is `main.py` L1744 in `_shutdown`, with the default timeout, inside a `try` that logs ERROR "zone_warmer.stop error: %s" (L1742 to L1746), after `signal_proc.stop()` (L1690), `retest_monitor.stop()` (L1731 to L1735) and `structure_exit_manager.stop()` (L1737 to L1741); the warmer reaches `_shutdown` as the parameter `zone_warmer` (L1615; A08 inventory, section 2.2).
- P02-S089 INTERPRETATION (shutdown; from L71 to L80, L103 to L119 and P02-S005 (b)): the sentinel wakes a worker that waits in `get`; a worker inside `warm` (a limiter wait or a broker call, P02-S039) is not interrupted, so `join` returns after 2.0 s without it; that daemon thread then completes its warm, which can still write to the cache and log after `stop` has returned, and leaves its loop, or it is "abruptly stopped" when the interpreter exits (P02-S005 (b)). A limiter wait ends early only through the limiter's own shutdown event (`RateLimitAbortedError`, P02-S038), which the fetcher logs as a WARNING "historical_data failed". `stop` neither drains nor clears the queue or `_pending`, so symbols still queued are not warmed. After `stop`, `enabled` is still true, so `enqueue` still accepts symbols into a queue that no worker reads; a `start` after a timed-out `stop` would start a second worker beside the first, because `_worker` was set to `None` (L80). Whether any of this happened in production is UNKNOWN / NOT ESTABLISHED.
- P02-S090 INTERPRETATION (the switches and `enabled`; from `main.py` L3545 to L3549, L3609, `signals/signal_processor.py` L365 to L366, and `sr_detector/zone_warmer.py` L63 to L64, L86): with `wait_for_retest_enabled` and `structure_exit_enabled` both false (the committed values) no warmer, zone cache or structure fetcher is built (`zone_warmer` and `_v2_zone_cache` stay `None`, L3545 to L3546), the processor receives `zone_warmer=None` (L3609) and `_warm_zones` returns at its first test (L365 to L366): nothing is queued or fetched for warming. With the structure exit on and the retest path off, the warmer is built and started (L3816) and warms every arriving symbol for the structure exit's reads. The constructor's `enabled=False` cannot be reached from `main.py`, which passes none (P02-S075); if it were false, `start` and `enqueue` would return at once while `warm` and `stop` would still act (the guard is in those two methods only).
