## 3. The closure `_make_sr_fetch_fn` and the `historical` bucket (C1, C3, I3, I4)

P06-S016. FACT (`main.py` L421 to L438): `_make_sr_fetch_fn(market_kite, rate_limiter)` returns the inner function `_fetch(instrument_token, from_date, to_date, interval)` (L428, L438). `_fetch` returns `[]` at once when `market_kite is None` (L429 to L430), before any limiter call; otherwise it calls `rate_limiter.acquire("historical")` (L431) and then returns `market_kite.historical_data(instrument_token=instrument_token, from_date=from_date, to_date=to_date, interval=interval)` (L432 to L437). P06-S018. FACT (`broker/rate_limiter.py` L76 to L99, L177 to L246): `acquire("historical")` with the default `n=1`: (a) if `n` exceeds the bucket's capacity it raises `BrokerRateLimitError` at once (L190 to L199; not the case at the committed capacity 2); (b) it loops: `bucket.try_acquire(1)` returns False while the bucket is frozen, otherwise refills the bucket from elapsed monotonic time and takes one token if one is there (L90 to L99), and `acquire` then returns (L205 to L211); (c) when 30 s have passed since the call began without a token, it raises `BrokerRateLimitError("Rate limit timeout after 30.0s waiting for 1 token(s) in category 'historical'", ...)` (L201 to L202, L213 to L223); (d) otherwise it sleeps for the estimated time to the next token, capped at the remaining time and at 0.1 s and at least 0.001 s (L225 to L233); with a shutdown event, as here, it waits on the event and raises `RateLimitAbortedError` if the event is already set when that wait starts or is set during it (`Event.wait` returns True at once for a set event; L236 to L244).

P06-S019. INTERPRETATION (code reading of `broker/rate_limiter.py` L205 to L244): the shutdown event is looked at only while a caller waits. When a token is available, `acquire` returns at once even if the event is already set, so a fetch that starts during shutdown still goes to the broker when the bucket holds a token; a caller that is waiting ends with `RateLimitAbortedError` within about 0.1 s of the event being set. At the committed rate a lone waiter gets its next token within about 0.5 s (arithmetic: one token at 2 per second). The limiter keeps no queue: several waiting threads each poll, and which of them gets the next token is not defined by the limiter.

P06-S020. FACT (`core/exceptions.py` L30, L158, L243, L284): `BrokerRateLimitError` subclasses `BrokerError`, which subclasses `TradingSystemError`, which subclasses `Exception`; `RateLimitAbortedError` subclasses `TradingSystemError`. INTERPRETATION (Python semantics): both are caught by an `except Exception` clause.

## 4. What a caller receives: outcomes case by case (C3, G3, I3)

P06-S024. FACT (`sr_detector/fetch.py` L114 to L136; A08's, boundary evidence): every consumer reaches the closure through `OhlcFetcher._fetch_one(symbol, token, interval, lookback_days=None)`. It first looks in its own cache (L118 to L120, outside the `try`). Inside a `try` (L121 to L129) it reads `now = self._now_fn()`, takes the lookback (`self._lookback_days`, or the argument when one is given), sets `from_dt = now - timedelta(days=lb)`, calls `rows = self._fetch_fn(token, from_dt, now, interval)`, converts `candles = [Candle.from_kite(r) for r in (rows or [])]`, caches the list only when it is not empty, and returns `candles or None`. `except Exception` (L130 to L136) logs WARNING "sr_detector fetch: historical_data failed for %s/%s: %s" with the symbol, the interval and the exception, and returns None.

P06-S025. INTERPRETATION (Python semantics; basis P06-S016 to P06-S024, and part P02, P02-S059 to P02-S061 and P02-S066 for the library's exceptions): what one fetch of one interval gives, case by case:

| Case | The closure `_fetch` | `_fetch_one` returns | Log line |
|---|---|---|---|
| No handle (`market_kite` None) | `[]` at once; no token taken | None; nothing cached | none |
| Token free or freed within 30 s | waits (at most 30 s), then one broker call | as for the broker call's outcome | none |
| Limiter timeout (30 s without a token) | raises `BrokerRateLimitError`; no broker call made | None | WARNING "... historical_data failed ..." with the limiter's text |
| Limiter abort (shutdown event set during the wait) | raises `RateLimitAbortedError`; no broker call made | None | the same WARNING |
| Broker or transport failure: a requests exception (for example a timeout), a kiteconnect exception chosen by the server's `error_type` (a 429 body included), `DataException`, or the edge-case `TypeError`, `KeyError` or `IndexError` | the exception propagates, untranslated | None | the same WARNING, with the exception's text |
| Empty answer (`candles` is an empty list) | `[]` | None; nothing cached | none |

## 7. The returned data contract: the library's row and `Candle.from_kite` (C4, I3, I5)

P06-S043. FACT (published kiteconnect 5.1.0 source, `connect.py` L624 to L670; part P02, P02-S063, P02-S065, checked): what the closure returns is the library's list: one dictionary per element `d` of `data["candles"]`, in the order received, with `date` = `dateutil.parser.parse(d[0])`, `open` = `d[1]`, `high` = `d[2]`, `low` = `d[3]`, `close` = `d[4]`, `volume` = `d[5]`, the values as the JSON decoder gave them, and `oi` = `d[6]` only when `d` has exactly seven elements (the closure asks for no OI, P06-S016). INTERPRETATION (part P02, P02-S066): a short row, a body without `candles`, or an unparseable time string ends the whole call with an exception, so the closure returns either the full list or nothing.

P06-S044. FACT (`sr_detector/models.py` L23 to L43; A08's file, boundary evidence): `Candle` is a frozen dataclass with six fields, `ts: datetime`, `open: float`, `high: float`, `low: float`, `close: float` and `volume: int`. `Candle.from_kite(row)` reads exactly six keys of a row: `date`, `open`, `high`, `low` and `close` with `row[...]`, and `volume` with `row.get("volume")`. It does not read `oi`. It sets `ts=row["date"]` unchanged, each price with `float(row[...])`, and `volume=int(row.get("volume") or 0)` (L36 to L43). HISTORICAL (L25, L35): "One OHLCV bar. ts is timezone-aware (or naive IST) datetime."; "Build from a kite.historical_data() dict row."

P06-S045. INTERPRETATION (Python semantics; own script, P06-S002; basis P06-S043 and P06-S044): (a) `from_kite` converts no time, attaches no zone and truncates nothing: `ts` is whatever `date` object the library made, aware with the server's offset or naive (part P02, P02-S066); (b) it rounds no price and uses no tick size: `float` keeps the decoded number's value; (c) a missing, `None` or zero volume becomes 0, and a fractional volume is truncated toward zero by `int`; (d) a missing `date`, `open`, `high`, `low` or `close` key raises `KeyError`, a `None` price raises `TypeError` and a non-numeric string raises `ValueError`, and any of them ends that interval's fetch with None (P06-S025); (e) it checks no relation between the prices (for example `high >= low`), no sign and no zero; (f) the field annotations are not enforced, so a `Candle` holds what it is given (also part P04, P04-S013); (g) a `Candle` carries no instrument token, symbol, interval or source: the consumer knows them only from its own request.

## 13. Points the AUDIT may examine (neutral)

1. The closure has no `try`, no translation and no 429 path; every failure, including a pacing timeout or a shutdown abort in which no broker call was made, ends as one WARNING worded "historical_data failed" and None in A08's fetcher (P06-S016, P06-S021, P06-S025; A04 RL-05).
2. An empty broker answer and every kind of failure reach the consumer in the same form (None, or a missing interval); an empty answer logs nothing (P06-S026).
3. The historical `ts` (the server's label; the start of the interval by the current examples and by a consumer's own code) and the live `ts` (the host's time at the close, the end of the interval) share one name and differ in meaning, precision and source (P06-S049 to P06-S052).
4. Whether a historical `ts` is aware or naive depends only on the server's string; `Candle.from_kite` does not normalise it; two consumers align or strip the zone by wall-clock digits (P06-S045, P06-S050, P06-S053).
5. Every window ends at the call time, so the last candle may be still forming; nothing on the A05 side marks or drops it (P06-S041).
6. All consumer threads of the trading process share one `historical` bucket at the committed 2 per second with a burst of 2, below the current documented 3 per second; the scripts pace separately or not at all (P06-S017, P06-S022, P06-S023, P06-S062; A04 RL-06).
7. A consumer thread can block for up to 30 s per interval waiting for a token, and a three-interval request can do so three times in turn (P06-S018, P06-S029).
8. The shutdown event is looked at only while a caller waits: a fetch that starts during shutdown goes to the broker when a token is free (P06-S019).
9. The fetcher's cache key leaves out the lookback window; at the committed constructions this has no effect (P06-S028; A08's fetcher).
10. The regime fetcher takes its cache TTL from `sr_detector.cache_ttl_sec`, not from the `regime` section (P06-S035).
11. The boot WARNING about a missing handle cannot be logged in Live, where the handle is always the adapter's client (P06-S014).
12. `scripts/sr_level_export.py` already fails at L139, before the L141 of A01 C38b (P06-S061; for the script's owner).
13. No code adjusts for corporate actions, and no result of the one-time adjustment check is recorded (P06-S063, P06-S064).
14. A `Candle` does not say which instrument, interval or source it came from, and its volume cannot tell a missing value from zero (P06-S045).
15. The comment above the flags ("Both default OFF") describes two flags, while the condition has six and `sr_detector.enabled` is committed `true` (P06-S033).
16. Legacy documents state the historical pacing as "~3/s" or "≤3 req/sec" and the shadow recorder's limiter as "the SAME" (P06-S057, P06-S077, P06-S078; A04 RL-06, RL-07).
