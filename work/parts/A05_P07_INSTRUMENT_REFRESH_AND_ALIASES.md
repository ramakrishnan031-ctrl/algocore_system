P07-S007. HISTORICAL (L1 to L33, the module docstring): the purpose is to "Build instruments.csv from three authoritative sources": "NSE security master CSV -- symbol universe", "NSE sector index CSVs -- sector classification" and "Kite Connect API -- instrument tokens, lot sizes, tick sizes" (L5 to L8); "Run on first setup and whenever NSE adds/removes symbols" (L10). Its "Locked Design Decisions" RI1 to RI15 (L12 to L28) say, in short: RI1 the security master defines the universe ("~2800 EQ-series symbols"); RI2 sector from `config/reference_data/index_members/` ("13 sector files"); RI3 `is_fno` from `fno_symbols.csv`, the security master's `fno_stock` column ignored; RI4 Kite provides token, lot size and tick size; RI5 PSU_BANK and PRIVATE_BANK override BANK; RI6 atomic write (`.csv.tmp`, then `os.replace()`); RI7 "abort (exit 1) if output row count < 1000"; RI8 `--account` takes `api_key_env` from `accounts.csv` and the access token from `data_store/session/zerodha_token.json`, "Fallback: env vars"; RI9 `--dry-run`; RI10 `--verbose`; RI11 "Only EQ-series rows from security master (series='eq'|'be'|'n'|'bt')"; RI12 "Symbols not matched in Kite: token=0, lot_size=1, tick_size=0.05"; RI13 `--csv` (default `config/instruments.csv`); RI14 "Exit codes: 0=success, 1=file/config error, 2=API/auth error"; RI15 the pure functions are testable without Kite. The usage section (L30 to L32) has one line that carries an account identifier (not reproduced) and one that sets the two generic environment names on the command line.
